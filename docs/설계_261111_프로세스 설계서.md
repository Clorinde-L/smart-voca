## 3. 프로세스 명세

### 3.1 PR-01 단어장 읽기·검증

| 항목 | 내용 |
|------|------|
| 함수 | `read_wordbook_csv(path) -> tuple[list[Word], list[ValidationIssue]]` |
| | `validate_wordbook_rows(rows) -> list[ValidationIssue]` — `rows` 는 `(line_no, 열 목록)` 의 목록 |
| 입력 | CSV 파일 경로 |
| 출력 | 위반이 없으면 `(단어 목록, [])`, 있으면 `([], 위반 목록)` |
| 예외 | 예외를 던지지 않는다. 파일 없음·디코딩 실패도 V-01 위반으로 돌려준다 |

**처리**
1. 파일을 `utf-8-sig` 로 열어 `csv` 모듈로 읽는다. 실패하면 V-01 을 돌려주고 끝낸다.
2. 완전히 빈 줄은 건너뛰되 줄 번호는 파일 기준으로 유지한다.
3. 첫 줄을 헤더로 검사한다(V-02). 실패하면 끝낸다.
4. 각 행에 V-03(열 2개) → V-04(빈 칸) → V-05(중복)를 검사해 위반을 모은다. 중복 비교는 `casefold` 한 영단어로 한다. V-03 에 걸린 행은 V-04, V-05 를 건너뛴다.
5. 위반이 없으면 V-06(단어 4개), V-07(서로 다른 뜻 4개)을 검사한다.
6. 위반이 없으면 앞뒤 공백을 뗀 `word`, `meaning` 에 0 부터 순번을 붙여 `Word` 목록을 만든다.

규칙 정의는 데이터 설계서 §6 을 따른다.

> **v1.3 (2026-11-25, ADR-28)**: 처리가 이렇게 바뀌었다.
> 1. 바이트를 `decode_csv_bytes` 가 `utf-8-sig` → `cp949` 순으로 글로 바꾼다. 올린 파일을 디스크에 쓰지 않기 위함이다.
> 2. 헤더는 `word,meaning` 과 `영단어,뜻` 둘 다 받는다(대소문자 무시).
> 3. 칸마다 `clean_text`(앞뒤 공백·연속 공백 정리)를 하고 길이(영단어 100자·뜻 300자)를 V-04 로 검사한다.
> 4. **파일 안 중복(V-05)은 위반이 아니다.** 앞줄을 쓰고 뒷줄 번호를 `duplicate_lines` 로 돌려준다.
> 5. V-06 은 "등록할 단어가 0개"로 바뀌었고, V-07(서로 다른 뜻 4개)은 가져올 때 검사하지 않는다. 보기를 만들 재료가 모자라면 시험지를 만들 때(PR-05) `ValueError` 로 알린다. 단어를 하나씩 등록·삭제할 수 있게 되어, 가져올 때만 막아서는 지킬 수 없기 때문이다.
>
> 출력은 `(ParsedWordbook, [])` 또는 `(None, 위반 목록)` 이다. 아래 시나리오 중 "대소문자만 다른 중복을 잡는다"는 "V-05 위반" 대신 "앞줄만 쓰고 `duplicate_lines == (5,)`" 가 된다.

**시나리오**

```
시나리오: 기본 단어장을 읽는다
  Given data/toeic_words.csv 가 있다
  When read_wordbook_csv 로 읽는다
  Then 단어 2,109개가 돌아오고 위반 목록은 비어 있다
  And 첫 단어의 index 는 0, 마지막 단어의 index 는 2108 이다

시나리오: BOM 이 없는 파일도 읽는다
  Given 같은 내용을 BOM 없는 UTF-8 로 저장한 파일이 있다
  When read_wordbook_csv 로 읽는다
  Then 첫 단어의 word 가 BOM 문자 없이 읽힌다

시나리오: 대소문자만 다른 중복을 잡는다
  Given 3번째 줄에 "Agenda", 5번째 줄에 "agenda" 가 있는 파일이 있다
  When read_wordbook_csv 로 읽는다
  Then 단어 목록은 비어 있다
  And V-05 위반 1건이 line_no 5 로 돌아온다

시나리오: 단어가 3개뿐인 파일을 거부한다
  Given 헤더와 단어 3줄만 있는 파일이 있다
  When read_wordbook_csv 로 읽는다
  Then V-06 위반이 돌아온다
```

### 3.2 PR-02 일차 편성

| 항목 | 내용 |
|------|------|
| 함수 | `build_days(word_count, day_size=DAY_SIZE) -> list[DayRange]` |
| 입력 | 단어 수(1 이상), 일차당 단어 수 |
| 출력 | 1일차부터 순서대로의 `DayRange` 목록 |
| 예외 | `word_count < 1` 또는 `day_size < 1` 이면 `ValueError` |

**처리**
1. 전체 일차 수 = `word_count` 를 `day_size` 로 나눈 값의 올림.
2. `day_no` 를 1 부터 늘리며 `start = (day_no - 1) × day_size`, `end = min(start + day_size, word_count)` 로 만든다.

`day_size` 를 인자로 둔 것은 테스트에서 작은 값으로 검증하기 위함이다. 프로그램은 항상 기본값 20 을 쓴다(기획서 v1.3).

> **v1.3 (VOCA-FR-011)**: `day_size` 는 기본값 없이 설정(`Settings.day_size`, 5~100)에서 받는다. `day_of(index, day_size)` 는 순번 하나의 일차 번호를 돌려준다(단어 관리 표의 일차 열).

**시나리오**

```
시나리오: 2,000 단어를 100일차로 나눈다
  Given 단어 수가 2000 이다
  When build_days 를 부른다
  Then 일차가 100개다
  And 1일차는 [0, 20), 100일차는 [1980, 2000) 이다

시나리오: 나누어떨어지지 않으면 마지막 일차가 짧다
  Given 단어 수가 2010 이다
  When build_days 를 부른다
  Then 일차가 101개이고 101일차는 [2000, 2010) 이다

시나리오: 모든 단어가 한 일차에만 속한다
  Given 단어 수가 45 이다
  When build_days 를 부른다
  Then 각 범위의 길이의 합이 45 다
  And 앞 일차의 end 와 다음 일차의 start 가 같다
```

### 3.3 PR-03 일차 상태 판정·진도 집계

> **v1.3 (ADR-26)**: 일차 기록(`DayRecord`)을 저장하지 않는다. 함수 모양은 아래와 같이 바뀌었다.
>
> | 함수 | 반환 |
> |------|------|
> | `day_status(day_words, studied_ids, tested_ids) -> DayStatus` | 그 일차의 모든 단어가 `tested_ids`(일차 시험에 나온 단어)에 있으면 `DONE`, 모든 단어가 `studied_ids`(암기 이력이 있는 단어)에 있으면 `MEMORIZED`, 그 밖은 `AVAILABLE`. 단어가 없는 일차는 `AVAILABLE` |
> | `all_day_statuses(words, days, studied_ids, tested_ids)` | 모든 일차의 상태 목록 |
> | `current_day(statuses) -> int \| None` | `DONE` 이 아닌 가장 작은 일차 |
> | `can_take_exam(status) -> bool` | `MEMORIZED` 또는 `DONE` |
> | `AppSession.summary() -> ProgressSummary` | 위 결과와 외운 단어 수(`studied_ids` 중 지금 단어장에 있는 것), 오답 목록 크기 |
>
> `studied_ids` 는 `repository.studied_word_ids`, `tested_ids` 는 `repository.day_tested_word_ids`(시험 종류 `day` 의 문항만)에서 온다. 실력·오답 시험은 일차를 완료하지 않는다. `reviewable_days` 는 없앴다. 아래는 v1.2 의 표이며 "`tested` 가 참"을 "모든 단어가 `tested_ids` 에 있음"으로 읽으면 시나리오가 그대로 성립한다.

| 함수 | 반환 |
|------|------|
| `day_status(progress, day_no) -> DayStatus` | 한 일차의 상태 |
| `current_day(progress, total_days) -> int \| None` | 완료하지 않은 가장 작은 일차. 모두 완료면 `None` |
| `progress_summary(progress, total_days) -> ProgressSummary` | `current_day`, `total_days`, `done_days`, `wrong_list_size` |
| `reviewable_days(progress, total_days) -> list[int]` | 암기 완료 이상인 일차 번호(오름차순). 2026-11-25 부터 화면은 쓰지 않는다(일차 목록이 전체를 보여 줌, ADR-22) |

**상태 판정 규칙** — 위에서부터 처음 맞는 것을 쓴다.

| 순서 | 조건 | 상태 |
|------|------|------|
| 1 | 그 일차의 `tested` 가 참 | `DONE` (완료) |
| 2 | 그 일차의 `memorized` 가 참 | `MEMORIZED` (암기 완료) |
| 3 | 그 밖 | `AVAILABLE` (학습 전) |

기록이 없는 일차는 `memorized`, `tested` 모두 거짓으로 본다. 날짜는 판정에 쓰지 않는다(FR-08). 2026-11-25 잠금을 없애 직전 일차를 보지 않는다(ADR-21). `current_day` 는 그대로 '완료하지 않은 가장 작은 일차'이고 화면은 이것을 오늘의 학습으로 추천한다.

### 3.4 PR-04 카드 진행·암기 완료

| 항목 | 내용 |
|------|------|
| 클래스 | `CardDeck(words)` — 일차 학습·복습·오답 학습 공용 |
| 속성 | `current -> Word`, `position -> int`(1 부터), `total -> int`, `can_next`, `can_prev`, `seen_all -> bool` |
| 메서드 | `next()`, `prev()` — 움직였으면 `True`, 끝이라 못 움직였으면 `False` |
| 함수 | `mark_memorized(progress, day_no)` — 그 일차의 `memorized` 를 참으로 만든다 |
| 예외 | `words` 가 비어 있으면 `ValueError` |

**처리**
1. 만들 때 위치를 첫 카드에 두고, 첫 카드를 "본 카드"에 넣는다.
2. `next()` / `prev()` 는 범위 안에서만 위치를 옮기고, 옮겨 간 카드를 "본 카드"에 넣는다.
3. `seen_all` 은 본 카드 수가 `total` 과 같을 때 참이다. 한 번 참이 되면 뒤로 가도 참이다.
4. `CardDeck` 은 학습 기록을 모른다. 일차 학습 화면이 `seen_all` 이 참이 되는 순간 `mark_memorized` 를 부르고 저장한다(이미 암기 완료 이상인 일차를 다시 보는 복습이면 부르지 않는다). 오답 학습은 오답 시험 버튼만 켠다.

`CardDeck` 은 저장되지 않는다. 화면을 나가면 사라지므로 도중에 나갔다 오면 첫 카드부터다(요구사항 명세서 D-03).

> **v1.3 (VOCA-FR-012 ~ 014)**:
> - `CardDeck` 은 `Word` 대신 `StudyCard`(단어 + 종류) 목록을 받는다. `cards` 속성으로 전부를 돌려준다.
> - 일차 카드는 `AppSession.day_cards(day_no)` 가 만든다. 그 일차 단어(`NEW`) 뒤에 복습 카드(PR-14)를 붙인다.
> - `mark_memorized` 는 없어졌다. 카드를 모두 보면 화면이 `AppSession.complete_memorize(day_no, cards)` 를 부른다. 이 메서드는 본 카드마다 `study_log` 에 (단어 번호, 영단어, 일차, 종류, 시각)을 한 줄씩 남긴다. 오답 학습은 `day_no = None` 이다.
> - 이미 끝낸 일차를 다시 학습해도 이력을 남긴다("언제 몇 번 외웠는지").
> - 카드를 보는 사이 단어가 지워졌으면 `word_id` 를 하위 쿼리(`SELECT id FROM word WHERE id = ?`)로 넣어 NULL 로 남긴다. 외래 키 오류를 막기 위함이다.
> - 화면은 같은 덱에서 한 번만 부른다(`CardStudy.logged`).

### 3.5 PR-05 시험지 생성

| 항목 | 내용 |
|------|------|
| 함수 | `build_exam(targets, wordbook, rng, direction=EN_KO, question_format=CHOICE) -> Exam` (v1.3) |
| 입력 | `targets`: 출제할 단어 목록. `wordbook`: 단어장 전체(오답 보기의 재료). `rng`: `random.Random` |
| 출력 | 문제 수가 `len(targets)` 인 시험지. 문제마다 보기 4개와 정답 위치 |
| 예외 | `targets` 가 비었거나, 단어장의 서로 다른 뜻이 4개 미만이면 `ValueError` |

**처리**
1. **보기 재료 만들기**: 단어장의 뜻을 등장 순서대로 훑어 서로 다른 뜻만 모은다. 시험지 하나에 한 번만 만든다.
2. **문제 순서 섞기**: `rng.sample(targets, len(targets))` 로 섞인 사본을 만든다. 원본 목록은 건드리지 않는다.
3. 섞인 순서대로 단어마다:
   1. 보기 재료에서 `rng.sample` 로 4개를 뽑는다.
   2. 뽑힌 것 중에 정답 뜻이 있으면 그것을 빼고, 없으면 마지막 것을 뺀다. 오답 보기 3개가 남는다.
   3. 정답 뜻과 오답 보기 3개를 합쳐 `rng.shuffle` 로 섞는다.
   4. 섞인 목록에서 정답 뜻의 위치를 `answer_index` 로 기록한다.

**설계 근거**
- 3.1 에서 4개를 뽑고 하나를 빼는 방식은 "정답과 다른 뜻 3개"를 반복 재시도 없이 한 번에 얻는다. 재료가 서로 다른 뜻뿐이므로 보기 4개는 항상 서로 다르다(FR-14).
- 뜻이 같은 단어가 둘 있어도(예: 동의어) 보기에 같은 문장이 두 번 나오지 않는다. 재료를 "다른 단어"가 아니라 "다른 뜻"으로 만들었기 때문이다.
- 난수는 `rng` 로만 쓰므로 같은 시드와 같은 입력이면 시험지가 같다(NFR-04).

> **v1.3 형식·방향 (ADR-27)**: 문제마다 처리가 이렇게 바뀌었다.
> 1. `resolve_direction` 으로 방향을 정한다. 섞기(`MIX`)면 `rng.choice` 로 영→한·한→영 중 하나를 고른다.
> 2. 방향에 따라 문제와 정답을 정한다. 영→한은 (`prompt` = 영단어, `answer` = 뜻), 한→영은 (`prompt` = 뜻, `answer` = 영단어).
> 3. 보기 후보(`_Pools`)를 고른다. 영→한은 서로 다른 뜻 모음, 한→영은 영단어 모음이다. 한→영에서는 정답과 뜻이 같은 다른 영단어도 정답으로 쳐서 보기에서 뺀다.
> 4. 오답 보기는 `_distractors(pool, n, excluded, rng)` 가 `n + len(excluded)` 개를 한 번에 뽑은 뒤 거른다. 다시 뽑는 반복이 없다는 점에서 처리 3.1 ~ 3.2 와 같은 생각이다.
> 5. 형식에 따라 문제를 만든다.
>    - **4지선다**: 정답 + 오답 3개를 섞는다.
>    - **OX**: `rng.random() < 0.5` 이면 맞는 짝을, 아니면 오답 보기 1개를 `shown` 으로 둔다. 보기는 `("O", "X")` 이고 `answer_index` 는 맞는 짝이면 0, 아니면 1 이다.
>    - **단답형**: 보기 없이 `prompt`·`answer` 만 둔다.
>
> 재료가 모자라면 `ValueError("보기를 만들 단어가 부족합니다 …")` 를 던진다. 화면은 이 문구를 알림 띠로 보여 준다.

**시나리오**

```

  Given 기본 단어장과 1일차 단어 20개가 있다
  When 시드 1 로 build_exam 을 부른다
  Then 문제가 20개다
  And 문제의 단어 집합이 1일차 단어 집합과 같다

  Given 기본 단어장과 1일차 단어 20개가 있다
  When 시드 1 로 build_exam 을 부른다
  Then 모든 문제의 보기가 4개이고 서로 다르다

### 3.6 PR-06 채점

| 항목 | 내용 |
|------|------|
| 함수 | `grade_exam(exam, answers) -> ExamResult` |
| 입력 | `answers`: 문제 순서대로 고른 보기 위치(0~3)의 목록 |
| 출력 | `total`, `correct_count`, `correct_words`(맞힌 단어), `wrong_items`(틀린 문제: 단어, 정답 뜻, 고른 뜻) |
| 예외 | 답 수가 문제 수와 다르거나, 답이 `None` 이거나 0~3 을 벗어나면 `ValueError` |

**처리**
1. 입력을 검사한다. 답하지 않은 문제가 있으면 채점하지 않는다(FR-15).
2. 문제마다 고른 위치가 `answer_index` 와 같으면 `correct_words` 에, 다르면 `wrong_items` 에 넣는다. 순서는 시험지의 문제 순서다.
3. `correct_count = len(correct_words)`, `total = len(questions)`.

채점은 학습 기록을 바꾸지 않는다. 반영은 PR-08, PR-09 이 한다.

> **v1.3 (ADR-27, VOCA-FR-025)**: 출력이 `ExamResult(items)` 로 바뀌었다. 문항마다 `ItemResult(question, given, correct)` 를 담고, 맞은 수·틀린 문항·단어 번호는 속성으로 계산한다.
> - **4지선다·OX**: 답은 보기 위치(정수)다. 범위를 벗어나면 `ValueError`. `given` 에는 고른 보기 글을 넣는다.
> - **단답형**: 답은 문자열이다. 비었으면 답하지 않은 것으로 보고 `ValueError` 를 던진다.
>   - 정오는 `is_short_answer_correct` 가 정한다.
>   - 한→영: 공백을 정리하고 대소문자를 무시해 영단어와 같으면 정답.
>   - 영→한: 품사 표시(`[명]`)와 `; , / ·` 로 뜻 칸을 나눈 조각(`meaning_parts`, 괄호 안을 뺀 형태도 포함) 중 하나와 같거나, 뜻 칸 전체와 같으면 정답. 띄어쓰기·괄호·물결표·마침표·하이픈은 비교에서 지운다.
>
> 예: 뜻이 `[명] 문제, 쟁점; (잡지의) 호 [동] 발행하다` 이면 `쟁점`, `발행 하다`, `호` 가 모두 정답이다.

**시나리오**

```
시나리오: 3개를 틀리면 17 / 20 이다
  Given 20문제 시험지가 있다
  When 17문제는 정답 위치를, 3문제는 다른 위치를 답으로 채점한다
  Then correct_count 는 17, total 은 20 이다

  Then ValueError 가 난다
```

### 3.11 PR-11 기록 복원·정합화·손상 처리

> **대체됨 (2026-11-25, ADR-25)**: 복원은 PR-16(DB 열기·테이블 준비)로 바뀌었다. 단어와 기록이 한 DB 에 있고 외래 키가 맞지 않는 기록을 막아 정합화(`reconcile_progress`)가 필요 없다. 단어를 지우면 오답 기록은 CASCADE 로 지워지고, 이력의 `word_id` 는 SET NULL 이 된다. 손상 파일 보존도 없다. 아래는 당시 기록이다.

### 3.14 PR-14 복습 카드 섞기 (v1.3)

| 항목 | 내용 |
|------|------|
| 함수 | `pick_review_cards(today_words, previous_day_words, frequent_wrong_words, count, rng) -> list[StudyCard]` |
| 입력 | 그날 단어, 전날 일차의 **외운** 단어, 오답 목록(많이 틀린 순), 복습 카드 수(설정), 난수 |

**처리**
1. 그날 단어와 겹치는 단어를 두 후보에서 뺀다.
2. 전날 단어를 `rng.shuffle` 로 섞는다. 오답은 많이 틀린 순서 그대로 둔다.

6. 이미 담은 단어는 다시 담지 않는다.

전날 단어 중 외운 것만 넘기는 일은 `AppSession.day_cards` 가 한다. 외우지 않은 단어를 "복습"으로 기록하면 암기 이력이 거짓이 되기 때문이다.

### 3.15 PR-15 가중 출제 (v1.3)

| 항목 | 내용 |
|------|------|
| 함수 | `word_weight(stat) -> float`, `pick_weighted(words, stats, count, rng) -> list[Word]` |
| 입력 | 후보 단어(외운 단어, 없으면 전체), 단어별 `WordStat`(`repository.word_stats`: 시험 횟수, 틀린 횟수, 마지막 시험 뒤 지난 날), 문제 수 |
| 출력 | 겹치지 않는 단어 `min(count, 후보 수)` 개 |
| 예외 | `count < 1` 이면 `ValueError` |

**처리**
1. 가중치 = `1 + 3·(시험 본 적 없음) + min(지난 날, 30)/10 + 2·min(누적 오답, 5)`.
   - 안 본 단어는 4.
   - 30일 넘게 안 본 단어는 4.
   - 5번 넘게 틀린 단어는 최대 11 + α.
2. 단어마다 열쇠 `u^(1/가중치)`(u 는 `rng.random()`)를 매기고 큰 순으로 `count` 개를 고른다(Efraimidis–Spirakis). 가중치가 클수록 열쇠가 1 에 가까워 잘 뽑히지만, 작은 단어도 뽑힐 수 있다.

**설계 근거**: 비복원 가중 추출을 정렬 한 번으로 끝내고, 난수 호출 수가 단어 수로 일정해 시드 재현이 쉽다(NFR-04).

```
시나리오: 안 본 단어가 더 자주 나온다
  Given 100단어 중 50개는 시험을 여러 번 봤고 다 맞혔다
  When 시드를 바꿔 20문제를 200번 뽑는다
  Then 안 본 단어의 평균 출제 수가 본 단어보다 크다

시나리오: 후보보다 많이 달라고 하면 있는 만큼 낸다
  Given 외운 단어가 5개다
  When 문제 수 20 으로 뽑는다
  Then 5개가 겹치지 않게 돌아온다
```

### 3.16 PR-16 DB 준비·기본 단어장 등록 (v1.3)

| 항목 | 내용 |
|------|------|
| 함수 | `init_db(db_path, default_csv_path, now) -> int` (넣은 기본 단어 수), `connect(db_path)`, `transaction(db_path)` |
| | `AppSession.open(db_path, default_csv)` — `init_db` 를 부른 뒤 세션을 만든다 |

**처리 — `init_db`**
1. `PRAGMA user_version` 이 0 이면 처음 만든 DB 다.
2. 테이블 7개와 색인을 `CREATE TABLE IF NOT EXISTS` 로 만든다.
3. 기본 사용자(id 1, `guest`)와 그 설정(기본값)을 `INSERT OR IGNORE` 로 넣는다.
4. 처음 만든 DB 면 `read_wordbook_csv(data/toeic_words.csv)` 로 읽어 단어를 넣는다. 읽지 못하면 `ValueError` 로 시작을 멈춘다.
5. `user_version` 을 스키마 버전(1)으로 쓴다. 그래서 사용자가 단어를 모두 지운 뒤 다시 켜도 기본 단어장이 되살아나지 않는다.

**처리 — `connect` / `transaction`**: 연결마다 `PRAGMA foreign_keys = ON` 과 `row_factory = sqlite3.Row` 를 켠다(대기 10초). `transaction` 은 `with` 블록이 끝나면 커밋하고, 예외가 나면 롤백한 뒤 다시 던진다. 연결은 블록이 끝나면 닫는다(요청마다 열고 닫음, gunicorn 워커 1개).

```

  When AppSession.open 을 다시 부른다
  Then 단어가 0개다

시나리오: 다시 열면 기록이 그대로다
