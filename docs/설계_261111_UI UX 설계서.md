### 1.1 설계 방향

| 방향 | 내용 | 근거 |
|------|------|------|
| 고민 없는 시작 | 메인 화면에서 가장 큰 버튼 하나로 오늘 할 일차를 바로 시작한다 | 기획서 §4 주요 기대, 현황·환경 분석서 I-01 |

## 2. 결정 기록

UD-01 ~ UD-04 는 `설계_261111_결정 기록.md` 로 옮겼다(대응은 §11). 이 절은 화면 설계의 맥락을 위해 남기며, 결정이 바뀌면 결정 기록을 기준으로 고친다.

### 2.1 UD-01 시험 중 정오 표시 시점

- **배경**: 요구사항 명세서 §6 에서 문제별 즉시 정오 표시 여부를 UI 설계로 넘겼다.
- **대안**: (a) 답을 고를 때마다 바로 정오 표시, (b) 모두 답한 뒤 제출하면 한꺼번에 표시.
- **결정 근거**: **(b) 채택.** FR-15("모든 문제에 답해야 제출")와 맞고, 제출 전까지 이전 문제로 돌아가 답을 고칠 수 있어 실제 시험과 비슷하다. (a) 는 정답을 본 뒤 도중에 나가 다시 응시하면(D-04 에 따라 미반영) 답을 알고 시험을 보게 되어 채점의 의미가 약해진다.

### 2.2 UD-02 화면 전환 방식

> **대체됨 (2026-11-25, UD-07 · ADR-19)**: 웹에서는 URL 하나가 화면 하나다. "한 번에 한 화면, 전이는 한곳에서 관리"라는 취지는 이어진다. 아래는 당시 결정이다.

- **배경**: 화면이 7개이고 전환이 잦다.
- **대안**: (a) 창 하나에서 화면만 교체(`QStackedWidget`), (b) 화면마다 새 창·대화상자.
- **결정 근거**: **(a) 채택.** 창이 여러 개 뜨면 "지금 어디인지"가 흐려지고 시험 중 다른 창을 조작하는 문제가 생긴다. 확인·알림·파일 선택만 대화상자로 띄운다.

### 2.3 UD-03 지난 일차 복습과 재시험의 진입점

- **배경**: 복습(FR-20)과 재시험(FR-19)은 대상이 같다(암기 완료 이상인 일차).
- **대안**: (a) 메인에 메뉴 두 개와 목록 화면 두 개, (b) "지난 일차" 목록 화면 하나에서 일차를 고른 뒤 복습·시험 중 선택.
- **결정 근거**: **(b) 채택.** 같은 목록을 두 번 만들지 않고 메인 메뉴가 줄어든다. 복습 카드 화면 안에는 시험 버튼을 두지 않으므로 FR-21 과 어긋나지 않는다.
- **확장 (2026-11-25, ADR-22)**: 잠금이 없어져(ADR-21) 목록이 전체 일차의 "일차 목록"(S-05)이 되고, 일차를 고르면 "일차 상세"(S-08)에서 학습·시험을 고른다. 복습 전용 카드 모드는 없앴다 — 끝낸 일차를 다시 학습하면 그것이 복습이다.

### 2.4 UD-04 뜻 가리기 옵션

- **배경**: 기획서는 카드에 영단어와 뜻을 함께 보여 주도록 정했다(FR-10). 한편 유사 앱은 뜻을 가렸다가 확인하는 방식이 공통이고(현황·환경 분석서 I-04), v1.0 에서는 개선 후보로만 두었다.
- **대안**: (a) 넣지 않음, (b) 항상 가리고 뒤집기, (c) 기본은 함께 보기, 사용자가 켜면 가리기.
- **결정 근거**: **(c) 채택.** 기본 동작이 FR-10 그대로라 요구사항을 바꾸지 않는다. 스스로 떠올려 보는 연습을 원하는 사용자는 체크 한 번으로 쓸 수 있다. 구현은 화면 상태 하나라 로직·저장에 영향이 없다.
- **영향**: 가린 채 넘겨도 "본 카드"로 센다(암기 완료 판정은 FR-12 그대로). 설정은 저장하지 않으며 프로그램을 다시 켜면 꺼져 있다.

### 2.5 UD-05 시험에서 답을 고르면 자동으로 다음 문제로

- **배경**: v1.0 은 고른 답을 확인할 틈을 주려고 자동으로 넘기지 않았다. 실제로 20문제를 풀면 매번 `다음` 이나 `→` 를 한 번 더 눌러야 해 번거롭다는 개선 요청이 있었다(2026-11-18).
- **대안**: (a) 지금처럼 넘기지 않음, (b) 고르는 즉시 넘김, (c) 잠시(0.3초) 뒤 넘김.
- **결정 근거**: **(c) 채택.** 0.3초 동안 선택 표시가 보여 무엇을 골랐는지 확인할 수 있고, 그 사이 다른 보기를 누르면 바꿀 수 있다. (b) 는 잘못 누른 것을 알아채기 어렵다. 이전 문제로 돌아가 고칠 수 있으므로(UD-01) 넘어가도 잃는 것이 없다.
- **영향**: 마지막 문제에서 답하면 아직 안 푼 첫 문제로, 모두 풀었으면 제출 버튼에 초점을 둔다(Enter 로 제출). 번호 점·이전/다음으로 직접 옮기거나 제출하면 기다리던 넘김은 취소한다. 정오는 여전히 제출 후에만 보여 준다(UD-01). 구현은 `ui/exam_page.py` 의 `AUTO_ADVANCE_MS`.

### 2.6 UD-06 단어 목록 화면에 전체 단어 검색표

- **배경**: v1.0 의 S-07 은 불러오기·내보내기 버튼만 있어, 단어장에 어떤 단어가 몇 일차에 있는지 프로그램 안에서 볼 수 없었다. 2,109개로 늘어나며 특정 단어를 찾아볼 필요가 커졌다(2026-11-18).
- **대안**: (a) 지금대로 둠, (b) 전체 표만, (c) 전체 표 + 검색.
- **결정 근거**: **(c) 채택.** 영단어·뜻으로 찾고, 숫자(`12`, `12일차`)를 넣으면 그 일차 단어 20개를 보여 줘 일차 미리보기로도 쓸 수 있다. 읽기 전용이라 학습 기록·단어장에 영향이 없다.
- **영향**: 표는 행마다 위젯을 만들지 않는 `QTableView` + 데이터 모델 + 거르개로 만든다(2,000개 넘는 행에서도 화면이 바로 열림). 단어장이 바뀔 때만 표를 다시 채운다. 불러오기·내보내기는 위쪽 작은 버튼 줄로 옮긴다. 요구사항 FR-29, 기능 F-01-09.
- **웹 전환 후 (2026-11-25)**: 서버가 검색 결과만 걸러 HTML 표로 보낸다. 글자를 칠 때마다가 아니라 `Enter` 로 검색한다(페이지를 다시 받으므로). 표 머리는 스크롤해도 위에 붙어 있다.

### 2.7 UD-07 웹 화면의 구성 방식

- **배경**: 교수님 요청으로 화면을 웹으로 바꾼다(2026-11-25, ADR-18). 내 PC 에 로컬 서버를 띄우고 브라우저로 본다.
- **대안**: (a) 서버가 화면마다 HTML 을 만들어 보냄(Flask 템플릿), (b) 한 페이지에서 JavaScript 가 API 를 불러 화면을 바꿈(SPA), (c) Python 전용 웹 UI 도구.
- **결정 근거**: **(a) 채택 (ADR-19).** 화면 하나가 URL 하나라 전이도(§4)와 코드가 1:1 로 맞는다. 판단은 서버가 하고 화면은 그리기만 한다는 원칙(§1.1)을 지키기 쉽다.
- **영향**: 카드 넘기기·문제 이동·답 고르기마다 페이지를 새로 받는다(내 PC 안이라 수 ms). JavaScript 는 단축키, 0.3초 자동 넘김(UD-05), 시험 중단 확인 대화상자(DL-03), 가린 뜻 열기(UD-04)만 맡는다. 진행 중인 카드·시험은 서버 메모리에 둔다. 서버를 끄면 사라진다. 처음(ADR-20)에는 하나만 두었으나, 학교 서버에 여러 사람이 접속하므로 2026-11-25 부터 브라우저(쿠키 ID)마다 따로 둔다(ADR-30). 같은 브라우저의 탭끼리는 진행을 공유한다.

- S-03 에서 '뒤로'·Esc 를 누르면 DL-03 을 띄운다. 웹에서는 탭을 닫거나 다른 주소로 가도 묻지 않는다 — 시험지는 서버에 남아 `/exam` 으로 돌아오면 이어서 풀 수 있고, 서버를 끄면 없던 것이 된다(ADR-12, ADR-20).
- 제출하거나 그만둔 뒤 브라우저 '뒤로'로 S-03 에 돌아오면 메인으로 보낸다(같은 시험을 두 번 제출할 수 없다).
- S-01 로 돌아올 때마다 진도 현황을 다시 그린다(FR-09).

- 정답·오답은 이 화면에서 보여 주지 않는다(UD-01).
- 보기를 고르면 0.3초 뒤 다음 문제로 넘어간다(UD-05). 마지막 문제에서는 안 푼 첫 문제로, 모두 풀었으면 제출 버튼에 초점을 둔다.
- 마지막 문제에서 답하지 않은 문제가 남아 있으면 제출 버튼 옆에 `답하지 않은 문제: 4, 11번` 을 보여 준다.

- 영단어 옆 발음 버튼(🔊, `P` 키)으로 들을 수 있다(FR-30). 시험 화면에는 메뉴 막대가 없다(§4).

**형식·방향 (v1.7, ADR-27)**: 문제 위에 `4지선다 · 영→한` 처럼 형식과 방향을 적는다. 섞기는 문제마다 방향이 다르다.

| 형식 | 문제 | 답하는 방법 | 자동 넘김 |
|------|------|-------------|-----------|
| 4지선다 | 영→한: 영단어(큰 글자, 발음 버튼) / 한→영: 뜻(문장 크기) | 보기 4개 중 고름(`1`~`4`) | 0.3초 (UD-05) |
| 단답형 | 위와 같다 | 입력 칸에 적고 `Enter`(또는 `답하기`). 비우면 답하지 않은 것. 돌아오면 적은 답이 그대로 보인다 | `Enter` 하면 바로 다음 문제 |
| OX | 위 + 보여 준 짝(뜻 또는 영단어) 하나와 `위 뜻이 이 단어의 뜻이 맞나요?` | `O` / `X` 두 보기(`1`·`2` 또는 `O`·`X` 키) | 0.3초 |

- 단답형의 채점 규칙(띄어쓰기·대소문자 무시, 뜻 조각 하나만 맞아도 정답)은 S-09 에 미리 적는다.

### 7.1 창·배치

### 7.3 긴 뜻 처리 (NFR-07)

- 카드의 뜻과 결과 표의 셀은 자동 줄바꿈을 켠다.
- 시험 보기는 **줄바꿈되는 글자 영역을 가진 선택 항목**으로 만든다. 웹에서는 `<button>` 안의 글자에 `white-space: normal; overflow-wrap: anywhere` 를 주어 줄바꿈하고, 줄이 늘면 보기 높이도 늘어난다. (PyQt 때는 줄바꿈 `QLabel` 을 담은 클릭 가능한 틀.)
- 말줄임표(…)로 자르지 않는다. 이 문서의 와이어프레임에 있는 `…` 는 지면 사정으로 줄인 것이다.
- 검증: 기본 단어장에서 뜻이 가장 긴 단어(53자, obsolete)의 카드와, 그 뜻이 든 보기를 브라우저 폭 800px 에서 띄워 전부 보이는지 확인한다. 자동 테스트는 뜻을 줄이지 않고 그대로 보내는지만 검사하고, 줄바꿈 모양은 스크린샷으로 확인한다.

### 7.4 버튼 상태

| 규칙 | 내용 |
|------|------|
| 비활성 이유 표시 | 조건이 있어 꺼진 버튼은 바로 옆에 이유를 적는다(시험 보기, 오답 시험, 제출) |
| 기본 버튼 | 화면마다 "다음에 할 일" 버튼 하나를 강조하고 Enter 에 연결한다 |
| 숨김과 비활성 | 그 화면에서 의미가 없는 것은 숨기고(시험 화면의 메뉴 막대, 첫 일차의 '이전 일차'), 조건을 채우면 쓸 수 있는 버튼은 비활성으로 보여 준다(학습 전 일차의 시험 보기) |

### 7.5 키보드

| 키 | 동작 | 화면 |
|----|------|------|
| `→` / `←` | 다음 / 이전 (S-08 에서는 이웃 일차) | S-02, S-03, S-08 |

| `Esc` | 뒤로 (S-03 에서는 DL-03). S-07 에서는 검색어를 지운다. 메뉴로 가는 화면(S-01, S-05, S-06)에서는 할 일이 없다 | S-02, S-03, S-07, S-08 |

### 7.6 색·표시

| 용도 | 규칙 |
|------|------|
| 강조 | 기본 버튼과 진도 막대에 한 가지 강조색만 쓴다 |
| 정답·오답 | S-04 의 표에서 정답 뜻과 고른 뜻을 색만으로 구분하지 않고 열 제목으로 구분한다 |
| 선택한 보기 | 배경색과 `● 선택` 표시를 함께 쓴다(색만으로 구분하지 않는다) |
| 상태 | `완료` / `암기 완료` 는 글자로 적고 색(초록 / 주황)을 함께 쓴다 |

색 값은 `src/smartvoca/web/static/style.css` 의 `:root` 변수 한곳에 둔다(PyQt 때는 `ui/theme.py`). 규칙에는 색 코드를 쓰지 않고 `var(--이름)` 만 쓴다. 밝은 테마의 강조색은 남보라(`#4f5bd5`) 하나이고 배경은 옅은 회색(`#f3f5fa`), 패널은 흰색이다.

**어두운 테마 (v1.6, ADR-23)**: 같은 변수에 어두운 값 묶음을 둔다(배경 `#0f1320`, 패널 `#181d2c`, 강조 `#7680ec`). 기본은 운영체제 설정을 따르고, 메뉴 막대의 테마 버튼으로 `자동 → 밝게 → 어둡게` 를 고른다. 고른 값은 이 브라우저(localStorage)에만 기억하고 학습 기록에는 넣지 않는다. 테마는 `<head>` 의 짧은 스크립트로 그리기 전에 적용해 밝은 화면이 번쩍이지 않게 한다. 상태 색(완료·시험 남음)은 두 테마 모두에서 글자와 함께 쓴다. v1.7 에서 더한 통계 막대, 복습·오답 카드 표시, 위험 버튼(삭제·바꾸기) 색도 같은 `:root` 변수만 쓴다.

### 7.7 문구

- 존댓말, 짧은 문장. 버튼은 동작을 적는다(`확인` 대신 `바꾸기`, `그만두기`).
- 번호는 사용자에게 1 부터 보여 준다(단어 순번, 줄 번호, 문제 번호).
- 오류 문구에는 무엇이 문제이고 어떻게 고치는지를 함께 적는다.

## 10. v1.1 구현 반영 사항

§5 의 와이어프레임은 배치의 뼈대이고, 실제 화면은 아래처럼 다듬었다. 요소의 동작과 조건은 §5 의 표 그대로다.

| 화면 | 바뀐 점 | 이유 |
|------|---------|------|
| 공통 | 색·글꼴·둥근 모서리·그림자를 `theme.py` 로 통일. '뒤로'는 테두리 없는 버튼, 화면마다 강조 버튼은 하나이고 오른쪽 아래에 둔다 | 다음에 할 일이 어디 있는지 화면마다 같게 |
| 공통 | 머리줄 오른쪽 정보(`7 / 20`, `문제 3 / 20`)를 알약 모양 표시로 | 위치 정보를 제목과 구분 |
| S-01 | 오늘의 학습을 강조색 배경의 큰 패널로, 진도 막대를 그 안에 배치 | 들어오자마자 할 일이 가장 크게 보이게 |
| S-01 | 현황 칸 3개 추가: 완료한 일차 / 시험까지 마친 단어 / 오답 단어 | 쌓인 양을 숫자로 보여 줘 동기 부여 (FR-09 범위 안) |
| S-01 | 메뉴 3개를 표식·제목·설명이 든 큰 버튼으로. 하단에 `Enter` 안내 | 메뉴가 무엇을 하는지 누르기 전에 알 수 있게 |
| S-02 | 머리줄 아래에 위치 막대 추가 | 몇 장 남았는지 한눈에 |
| S-02 | `뜻 가리고 외우기` 체크와 `뜻 보기 (Space)` 버튼 추가 | UD-04 |
| S-03 | 문제 번호 점 추가: 답한 문제는 색을 채우고 현재 문제는 굵은 테두리. 누르면 그 문제로 이동. 문제가 60개를 넘으면 점 대신 막대 | 답하지 않은 문제를 찾아가기 쉽게 (FR-15) |
| S-03 | 보기 번호를 동그란 표시로, 선택 표시는 `✓ 선택` | 색과 글자 두 가지로 선택을 구분 |
| S-04 | 점수를 고리 그림(맞은 수 / 전체, 정답률)과 한 줄 격려 문구로 | 결과를 한눈에. 고리 색은 정답률 90% 이상 초록, 60% 이상 남보라, 그 밖 주황이며 숫자를 항상 함께 적는다 |
| S-05 ~ S-06 | 표에 줄무늬·행 강조, 단어 열 굵게 | 긴 목록에서 줄을 따라가기 쉽게 |
| S-07 | 동작마다 제목·설명·버튼을 한 줄 패널로 | 버튼이 무엇을 하는지 옆에서 바로 설명 |
| 창 | 앱 아이콘을 코드로 그려서 지정 | 그림 파일 배포 불필요 |

추가된 공용 부품(`ui/widgets.py`): `MenuCard`, `StatTile`, `QuestionDots`, `ScoreRing`. 단축키에 `Space`(뜻 보기)를 더했다.

**v1.4 (2026-11-18)**: 색은 그대로 두고 편의 기능을 더했다. 시험 자동 넘김(UD-05), 단어 목록 검색표(UD-06), 단축키 안내 줄(`KeyHints`, S-01·S-02·S-03·S-07), 지난 일차 상태 색, 시험 문제를 세로 가운데로 배치. 메인의 단어 목록 메뉴 설명은 `전체 단어 검색·불러오기`.
