## 2. 결정 기록

### ADR-01 UI 라이브러리는 PyQt6

> **대체됨 (2026-11-25, ADR-18)**: 화면을 Flask 웹으로 바꾸며 PyQt6 를 쓰지 않는다. 아래는 당시 결정이다.

- **배경**: 기획서 §8.3 에서 Python + PyQt 를 확정하고 세부 버전을 설계 단계로 넘겼다.
- **대안**: (a) PyQt6, (b) PyQt5, (c) PySide6.
- **결정 근거**: **(a) PyQt6.** 현재 유지되는 주 버전이고 Python 3.12 용 배포본을 `pip` 로 바로 설치할 수 있다. 고해상도 화면 배율을 기본으로 처리해 Windows 11 노트북에서 글자가 흐려지지 않는다. PyQt5 는 자료가 많지만 Qt 5 가 유지보수 단계라 새로 시작할 이유가 약하다. PySide6 는 API 가 거의 같지만 기획서가 PyQt 로 정했으므로 따른다.
- **영향**: 열거형을 전체 이름으로 써야 한다(`Qt.AlignmentFlag.AlignCenter`). PyQt5 예제 코드를 그대로 옮기면 오류가 난다. PyQt6 는 GPL v3 이므로 프로그램을 배포하면 같은 조건이 적용된다(실습·비공개 저장소에서는 문제없음).

### ADR-02 학습 기록은 JSON 파일 1개

> **대체됨 (2026-11-25, ADR-25)**: 이력·통계 요구로 SQLite 로 옮겼다. 아래는 당시 결정이다.

- **배경**: 기획서 §7 에서 JSON / SQLite 선택을 설계 단계로 넘겼다. 저장 대상은 일차 100여 건, 단어 기록 최대 2,000건이다.
- **대안**: (a) JSON 파일 1개, (b) SQLite, (c) 종류별 CSV 여러 개.
- **결정 근거**: **(a) JSON.** 데이터가 작아 매번 전체를 써도 부담이 없고, 메모장으로 열어 확인·수정할 수 있어 디버깅과 학습에 좋다. 표준 라이브러리만 쓴다. SQLite 의 트랜잭션은 임시 파일에 쓰고 `os.replace` 로 교체하는 방식으로 대신한다. (c) 는 파일 사이 정합성을 따로 맞춰야 한다.
- **영향**: 저장할 때마다 파일 전체를 다시 쓴다. 시험 응시 이력이나 통계(기획서 §10.2)를 쌓게 되면 SQLite 로 옮긴다. 이를 위해 `schema_version` 을 둔다.

### ADR-03 단어장을 바꾸면 확인 후 기록 초기화

- **배경**: 기획서 §6.7 의 미결 사항이다. 학습 기록은 단어장의 순서·구성에 묶여 있어 단어장이 바뀌면 "3일차 완료"가 가리키는 단어가 달라진다.
- **대안**: (a) 확인 후 초기화, (b) 단어장별 기록 분리 보관, (c) 같은 영단어의 오답 기록만 승계.
- **결정 근거**: **(a).** 구현·테스트가 단순하고 기록과 단어장이 어긋날 여지가 없다. (b) 는 단어장 식별·목록 관리 기능이 추가로 필요해 범위가 커진다. (c) 는 일차 진도를 옮길 수 없어 기록이 반쪽만 남는다.
- **영향**: 단어장을 바꾸면 이전 기록을 되돌릴 수 없다. 확인 대화상자(DL-01)의 기본 버튼을 `취소` 로 두고 오답 목록 내보내기를 안내해 보완한다.

### ADR-04 오답 보기 추출 방식

- **배경**: 4지선다의 오답 보기 3개는 정답과 달라야 하고 서로도 달라야 한다(FR-14). 기본 단어장에는 뜻이 완전히 같은 단어가 있다(2,000 단어 중 서로 다른 뜻 1,983개, 2026-11-11 확인. 2026-11-18 교체한 2,109 단어 중에서는 2,105개).
- **대안**: (a) 다른 **단어** 3개를 무작위로 뽑는다, (b) 조건에 맞을 때까지 다시 뽑는다, (c) 단어장의 **서로 다른 뜻** 모음에서 4개를 뽑고, 정답이 들어 있으면 그것을, 없으면 마지막 것을 뺀다.
- **결정 근거**: **(c).** (a) 는 뜻이 같은 단어가 뽑히면 정답과 같은 문장이 보기에 두 번 나온다. (b) 는 반복 횟수가 정해지지 않아 테스트가 번거롭다. (c) 는 한 번의 추출로 조건을 항상 만족하고, 난수 호출 횟수가 일정해 같은 시드에서 결과가 같다.
- **영향**: 단어장에 서로 다른 뜻이 4개 이상 있어야 한다. 검증 규칙 V-07 로 불러올 때 막는다. 비슷한 품사·주제끼리 보기를 묶는 난이도 조절은 하지 않는다.

### ADR-05 계층 분리와 `AppSession`

- **배경**: 기획서 §8.3 이 로직과 UI 의 분리를 방침으로 정했다(NFR-03). 로직을 화면 없이 테스트해야 한다(NFR-04).
- **대안**: (a) 화면 클래스 안에 로직을 함께 작성, (b) 로직·UI 두 계층, (c) 도메인 로직·데이터 접근·응용(`AppSession`)·UI 네 부분.
- **결정 근거**: **(c).** (a) 는 PyQt 없이 테스트할 수 없다. (b) 는 "채점 → 기록 반영 → 저장" 같은 순서를 화면마다 반복해 쓰게 되어 저장을 빠뜨리기 쉽다. (c) 는 그 순서를 `AppSession` 한곳에 두므로 화면은 메서드 하나만 부르면 되고, 세션까지를 화면 없이 테스트할 수 있다.
- **영향**: 모듈 수가 늘어난다. UI 는 `storage` 를 직접 부르지 않는다. 의존 방향은 테스트로 검사한다(시스템 구조 §2.1).

### ADR-06 사용자 데이터 위치는 `userdata/`

> **2026-11-25 (ADR-25, ADR-29)**: 로컬 실행은 `userdata/voca.db` 를 쓰고, 서버는 환경변수 `DB_PATH`(`/data/voca.db`)를 따른다.

- **배경**: 학습 기록과 불러온 단어장 사본을 둘 곳이 필요하다. 프로그램은 기본 CSV 와 사용자의 원본 CSV 를 덮어쓰지 않는다(NFR-06).
- **대안**: (a) 프로젝트 루트의 `userdata/`, (b) `%APPDATA%\smart-voca\`, (c) `data/` 안.
- **결정 근거**: **(a).** 소스에서 직접 실행하므로 프로젝트 폴더 안에 있어야 찾고 지우기 쉽다. (c) 는 커밋되는 기준 데이터와 개인 기록이 섞인다.
- **영향**: `userdata/` 를 `.gitignore` 에 넣는다. 프로젝트 폴더를 지우면 기록도 사라진다. exe 로 배포하게 되면 (b) 를 다시 검토한다. 저장소 코드는 기준 디렉토리를 인자로 받으므로 위치가 바뀌어도 로직은 그대로다.

### ADR-07 단어 기록의 키는 영단어

> **대체됨 (2026-11-25, ADR-25)**: 단어를 수정할 수 있게 되어(VOCA-FR-002) 키를 DB 의 `word.id` 로 바꿨다. 이제 철자를 고쳐도 기록이 이어진다.

- **배경**: 단어별 오답 기록을 단어장의 어느 값에 묶을지 정해야 한다.
- **대안**: (a) 영단어 문자열, (b) 단어장 내 순번.
- **결정 근거**: **(a).** 영단어는 단어장 안에서 유일하다(V-05). 기본 단어장의 뜻을 검수해 고치거나 줄 순서가 바뀌어도 기록이 다른 단어에 붙지 않는다. 기록 파일을 사람이 읽기 쉽다.
- **영향**: 영단어의 철자를 고치면 그 단어의 오답 기록은 이어지지 않는다(ADR-13 에 따라 버려진다).

### ADR-08 Python 3.12, 가상환경, `src` 배치

### ADR-13 기록과 단어장이 어긋나면 맞지 않는 항목만 버림

> **대체됨 (2026-11-25, ADR-25)**: 단어와 기록이 한 DB 에 있고 외래 키(CASCADE / SET NULL)가 어긋남을 막으므로 정합화 단계가 없어졌다.

- **배경**: 기본 단어장은 사용자 검수 후 고쳐질 수 있다(기획서 §7). 단어장 교체 도중 프로그램이 꺼질 수도 있다. 이때 기록 파일은 읽히지만 단어장과 맞지 않는 항목이 생긴다.
- **대안**: (a) 맞지 않는 항목만 버리고 나머지는 유지, (b) 어긋남을 감지하면 기록 전체 초기화, (c) 그대로 사용.
- **결정 근거**: **(a).** 뜻을 고치거나 단어 몇 개를 바꾼 정도로 진도 전체를 잃는 것은 지나치다. (c) 는 없는 단어의 기록 때문에 오답 목록 처리에서 오류가 난다.
- **영향**: 단어 순서를 크게 바꾸면 "완료한 일차"의 단어 구성이 달라질 수 있다. 사용자가 직접 불러오는 단어장 교체는 ADR-03 에 따라 초기화하므로 이 규칙은 기본 단어장 수정과 비정상 종료에만 적용된다.

### ADR-14 카드의 뜻 가리기는 기본 꺼짐인 선택 옵션

- **배경**: 기획서는 카드에 영단어와 뜻을 함께 보여 주도록 정했다(FR-10). 한편 유사 앱은 뜻을 가렸다가 확인하는 방식이 공통이고(현황·환경 분석서 I-04), UI/UX 설계서 v1.0 에서는 개선 후보로만 두었다. 화면 디자인을 다듬는 중에(2026-11-11) 넣을지를 정했다.
- **대안**: (a) 넣지 않음, (b) 항상 가리고 뒤집어 확인, (c) 기본은 함께 보기, 사용자가 켜면 가리기.
- **결정 근거**: **(c).** 기본 동작이 FR-10 그대로라 요구사항을 바꾸지 않는다. (b) 는 FR-10 과 어긋나고, 뜻을 훑어보며 외우고 싶은 사용자에게 매번 한 번 더 누르게 한다. (c) 는 스스로 떠올려 보는 연습을 원하는 사용자가 체크 한 번으로 쓸 수 있고, 구현이 카드 화면의 상태 하나라 로직·저장에 영향이 없다.
- **영향**: 카드 화면(S-02)에 `뜻 가리고 외우기` 체크와 `뜻 보기 (Space)` 버튼이 생긴다(`ui/card_page.py`). 가린 채 넘겨도 "본 카드"로 센다(암기 완료 판정은 FR-12 그대로). 설정은 저장하지 않으며 프로그램을 다시 켜면 꺼져 있다. 설정을 기억하게 하려면 학습 기록과 분리된 설정 저장 방식을 따로 정해야 한다.

### ADR-15 기본 단어장을 토익 단어목록 PDF(2,109개)로 교체

- **배경**: 기존 기본 단어장(2,000개)은 주제 11묶음 순서이고 묶음 안이 거의 알파벳 순이라, 1일차가 a 로 시작하는 사무 단어로만 채워졌다. 사용자가 토익 단어목록 PDF(`ai-agent/uploads/토익 단어목록.pdf`, 2,109개, "누구나 자유롭게 이용하고 공유" 표기)를 제공하며 이것으로 바꾸기를 요청했다(2026-11-18).
- **대안**: (a) 기존 단어장을 고정 시드로 섞기(주제 안 / 전체 / 주제 번갈아), (b) PDF 단어장으로 교체. (b) 안에서 단어 수 2,109 / 2,100 / 2,000, 겹치는 959개의 뜻을 PDF / 기존 중 무엇으로 할지, 파일명 유지 / 변경을 정했다.
- **결정 근거**: **(b), 2,109개 전부, 뜻은 PDF 그대로, 파일명 `data/toeic_words.csv`.** 사용자가 고른 자료를 그대로 쓰고 뜻 출처를 하나로 통일한다. 일차 편성(FR-07)은 개수가 나누어떨어지지 않아도 동작하므로 코드 변경이 없다. 파일명에서 개수를 빼 다음 교체 때 이름이 어긋나지 않게 한다.
- **영향**: 106일차(마지막 9개). 원본은 `ai-agent/claude/261118_PDF단어장/data/toeic_words.tsv`, 생성은 같은 폴더의 `script/build_csv.py`. 기존 원본 `261021_토익단어2000/` 은 기록으로 남긴다. 학습 기록 키가 영단어(ADR-07)이고 일차 번호가 바뀌므로 기존 기록이 있었다면 맞지 않는다 — 교체 시점에 기록이 없어(`userdata/` 없음) 영향 없음. PDF 뜻은 검수 전이다.

### ADR-16 시험에서 답을 고르면 0.3초 뒤 자동으로 다음 문제로

### ADR-17 단어 목록 화면에 전체 단어 검색표

- **배경**: 단어 목록 화면(S-07)은 불러오기·내보내기만 있어 어떤 단어가 몇 일차에 있는지 볼 수 없었다. 단어가 2,109개로 늘며 찾아볼 필요가 커졌다(2026-11-18).
- **대안**: (a) 현행 유지, (b) 전체 표만, (c) 전체 표 + 검색(영단어·뜻·일차 번호).
- **결정 근거**: **(c).** 검색 하나로 단어 찾기와 일차 미리보기를 함께 해결한다. 읽기 전용이라 학습 기록에 영향이 없다. 표는 `QTableView` + 데이터 모델로 만들어 2,000개 넘는 행에서도 바로 열린다(행마다 위젯을 만드는 `QTableWidget` 은 열 때마다 느려진다).
- **영향**: 요구사항 FR-29, 기능 F-01-09 추가. 일차 번호는 일차 편성(FR-07)과 같은 규칙(순번 ÷ 20 + 1)으로 화면에서 계산하며 저장하지 않는다.
- **웹 전환 후 (2026-11-25)**: 검색 규칙은 `web/wordsearch.py` 의 `filter_words` 로 옮겼다. 서버가 검색 결과를 거른 HTML 표를 보내며, 검색은 `Enter` 로 한다.

### ADR-18 화면을 PyQt6 데스크톱에서 로컬 Flask 웹으로 교체 (ADR-01 대체)

> **2026-11-25 (ADR-29, ADR-30)**: 기말 과제로 학교 서버에도 올린다. "127.0.0.1 전용, Host 허용 목록"은 로컬 실행에만 남는다. 서버에서는 0.0.0.0:8080 에서 듣고, 출처는 호스트만 비교한다.

- **배경**: 교수님이 웹으로 구현하라고 하셨다(2026-11-25). ADR-01 은 PyQt6 데스크톱을 택했다.
- **대안**: (a) 인터넷에 배포해 여러 사용자가 접속, (b) 서버 없는 정적 페이지(기록은 브라우저 localStorage), (c) 내 PC 에서 도는 로컬 웹 서버를 브라우저로 사용.
- **결정 근거**: **(c).** (a) 는 로그인·사용자별 저장·호스팅이 필요하고 오프라인(NFR-02)·개인정보(NFR-09) 요구사항을 다시 써야 한다. (b) 는 로직을 JavaScript 로 다시 짜야 해 Python 로직과 테스트를 버리게 된다. (c) 는 로직·저장 계층과 요구사항을 그대로 두고 UI 계층만 바꾼다. 계층 분리(ADR-05) 덕분에 `core`·`storage`·`session.py` 는 한 줄도 고치지 않았다.
- **영향**: 서버는 `127.0.0.1:8765` 에만 연다(다른 기기에서 접속 불가). 주소(Host)가 내 PC 가 아니거나 다른 사이트에서 보낸 POST 는 거절한다. 이미 실행 중이면 서버를 하나 더 띄우지 않는다(두 서버가 같은 `progress.json` 을 덮어쓰지 않게). NFR-01 을 고쳤다. PyQt6 의존성과 `src/smartvoca/ui/` 를 지웠다.

### ADR-19 웹 화면은 Flask + 서버 렌더링 템플릿 (ADR-09 대체)

- **배경**: 웹 화면을 만드는 방식을 정해야 한다.
- **대안**: (a) Flask + Jinja2 템플릿(서버가 HTML 을 만듦), (b) FastAPI JSON API + JavaScript 화면, (c) NiceGUI 같은 Python 전용 웹 UI.
- **결정 근거**: **(a).** 요청·응답·폼·리다이렉트라는 웹의 기본 구조가 코드에 그대로 드러나 배우기 좋다. 판단(카드를 다 봤는가, 제출할 수 있는가)을 모두 서버(Python)가 하므로 "화면은 판단하지 않음" 원칙(UI/UX 설계서 §1.1)을 지키기 쉽다. (b) 는 화면 로직이 JavaScript 로 넘어가 분량이 늘고, (c) 는 웹 구조를 감춰 학습 목적에 덜 맞는다.
- **영향**: 화면 하나가 URL 하나다. 기록·진행을 바꾸는 요청은 POST 로 보내고 처리 뒤 GET 화면으로 리다이렉트한다(새로고침해도 두 번 제출되지 않음). 카드 넘기기·문제 이동마다 페이지를 새로 받는다(로컬이라 수 ms). JavaScript 는 단축키, 0.3초 자동 넘김(ADR-16), 시험 중단 확인 대화상자만 맡는다.

### ADR-20 진행 중인 카드·시험은 서버 메모리에 하나만 둔다

> **대체됨 (2026-11-25, ADR-30)**: 서버에 여러 사람이 접속하므로 상태를 브라우저마다 따로 둔다. 서버 메모리에 두는 이유(정답을 브라우저로 보내지 않음)는 그대로다.

- **배경**: 웹은 요청마다 끊기므로 카드 위치, 고른 답 같은 진행 상태를 어딘가에 들고 있어야 한다. PyQt 에서는 화면 위젯이 들고 있었다.
- **대안**: (a) 서버 메모리의 `WebState` 하나, (b) 브라우저 쿠키·폼 숨김 칸, (c) 파일에 저장.
- **결정 근거**: **(a).** 사용자가 1명이고 서버가 내 PC 에만 있으므로 상태 하나면 충분하다. (b) 는 시험지의 정답 위치가 브라우저로 넘어가 답을 볼 수 있다. (c) 는 도중에 나간 암기·시험을 저장하지 않는다는 ADR-12 와 어긋난다.
- **영향**: 서버를 끄면 진행 중인 카드·시험은 사라진다(ADR-12 와 같은 결과). 탭을 여러 개 열면 같은 상태를 공유한다. 서버는 한 번에 요청 하나만 처리(`threaded=False`)해 `AppSession` 을 동시에 바꾸지 않는다. 상태 규칙(자동 넘김, 제출 조건)은 Flask 를 모르는 `web/state.py` 에 두어 따로 테스트한다.

### ADR-21 일차 잠금 폐지 (FR-08 변경)

- **배경**: N일차 시험을 내야 N+1일차가 열렸다. 사용자는 일차 목록에서 원하는 일차를 골라 보고 싶어 한다(이미 아는 일차를 건너뛰거나, 시험 범위를 미리 보는 경우).
- **대안**: (a) 잠금 폐지, (b) 잠긴 일차는 미리보기만, (c) 잠금 유지.
- **결정 근거**: **(a).** 대학생 토익 준비는 시험 범위·약한 부분에 따라 순서를 바꾸는 일이 많다. 순서를 강제하는 대신 '오늘의 학습'에서 완료하지 않은 가장 앞 일차를 추천해 기본 흐름은 유지한다. 응시 조건(카드를 다 봐야 시험, FR-12·FR-13)은 그대로 둔다.
- **영향**: `DayStatus.LOCKED` 를 없앴다. 상태는 `학습 전 / 암기 완료 / 완료` 셋. `core/schedule.py` 의 `day_status`, `session.complete_memorize` 의 범위 검사를 고쳤다. 저장 형식(progress.json)은 바뀌지 않아 기존 기록이 그대로 읽힌다. 시험 결과의 문구가 `N+1일차가 열렸습니다` 에서 `다음 추천은 M일차입니다` 로 바뀌었다. FR-08, FR-13, FR-18, FR-28 수정.

### ADR-22 일차 목록·일차 상세 화면과 공통 메뉴 막대 (ADR-11 확장)

- **배경**: 잠금이 없어지면 "지난 일차"(암기 완료 이상만)라는 구분이 의미를 잃는다. 다른 메뉴로 가려면 매번 메인으로 돌아가야 했다.
- **대안**: (a) 일차 목록(전체) → 일차 상세(단어 20개, 학습·시험) 두 단계, (b) 목록 한 화면에 행마다 버튼.
- **결정 근거**: **(a).** 상세 화면에서 그 일차의 단어를 먼저 훑어보고 학습·시험을 고를 수 있다. 복습과 첫 학습이 같은 카드 화면(일차 학습)으로 합쳐져 화면 모드가 줄어든다. 공통 메뉴 막대(홈·일차·오답 학습·단어 목록·테마)로 어느 화면에서든 한 번에 이동한다. 시험 화면에서는 메뉴 막대를 숨겨 실수로 나가지 않게 한다.
- **영향**: S-05 를 "일차 목록"(`/days`, 상태 거르기 탭)으로 바꾸고 S-08 "일차 상세"(`/days/<n>`)를 더했다. 메인에 '일차 한눈에'(전체 일차 칸)를 더했다. 카드의 복습 모드(`CardMode.REVIEW`)와 `/study/review` 를 없앴다 — 끝낸 일차를 다시 학습해도 기록은 바뀌지 않으므로(FR-12 는 `학습 전` 일차만 기록) 복습과 같고, 시험 버튼이 보이는 점만 다르다. FR-20, FR-21 수정.

### ADR-23 어두운 테마

- **배경**: 밤에 공부할 때 밝은 화면이 눈부시다. UI/UX 설계서 §9 개선 후보에 있던 항목.
- **대안**: (a) 운영체제 설정을 따르고 메뉴 막대 버튼으로 자동/밝게/어둡게 전환, (b) 버튼 전환만.
- **결정 근거**: **(a).** 기본은 운영체제를 따라 따로 설정할 필요가 없고, 원하면 바꿀 수 있다. 선택은 브라우저(localStorage)에 기억한다 — 학습 기록이 아니라 보기 설정이라 progress.json 에 넣지 않는다.
- **영향**: 모든 색을 `style.css` 의 `:root` 변수로 옮기고 어두운 값 묶음을 두었다. 테마는 CSS 를 그리기 전에 `<head>` 의 짧은 스크립트로 적용해 화면이 번쩍이지 않게 한다.

### ADR-24 발음 듣기는 브라우저 내장 음성 합성

- **배경**: 단어를 눈으로만 외우면 듣기 파트에서 못 알아듣는다.
- **대안**: (a) 브라우저 Web Speech API(`speechSynthesis`), (b) 외부 발음 API, (c) 발음 파일 동봉.
- **결정 근거**: **(a).** 설치·파일이 필요 없다. Windows 에 기본으로 들어 있는 영어 음성(내 PC 음성)을 먼저 골라 인터넷 없이 동작한다(NFR-02). (b) 는 오프라인 요구사항에 어긋나고, (c) 는 2,109개 파일을 만들어야 한다.

### ADR-25 저장소를 SQLite 로 전환 (ADR-02 대체)

- **배경**: 기말 과제(소프트웨어 요건 v1.1)는 세 가지를 요구한다. 암기·시험 이력을 DB 에 문항 단위로 남기고(VOCA-FR-014, 026), 통계를 DB 이력으로 계산하고(VOCA-FR-034), DB 는 SQLite 를 쓴다(VOCA-NFR-002). ADR-02 에도 "이력·통계를 쌓게 되면 SQLite 로 옮긴다"고 적어 두었다.
- **대안**: (a) JSON 유지 + 이력만 SQLite, (b) 단어·이력·설정 모두 SQLite, (c) PostgreSQL(11-30 까지 사전 협의 필요).
- **결정 근거**: **(b).** 단어 등록·수정·삭제(VOCA-FR-001·002), 이력, 통계 집계가 한 DB 에 있어야 SQL 로 바로 묶어 계산할 수 있다. 저장소가 둘이면 서로 어긋날 수 있다. `sqlite3` 는 표준 라이브러리라 의존성이 늘지 않는다. 서버(`/data/voca.db`)·로컬(`userdata/voca.db`) 모두 파일 하나다. (c) 는 사전 협의와 접속 재시도 처리가 필요한데 얻는 이점이 없다.
- **영향**:
  - **모듈**: `storage/db.py`(연결, 테이블 자동 생성, 기본 단어장 등록)와 `storage/repository.py`(모든 SQL)를 새로 두었다. `progress_store.py`·`fileutil.py`·`progress.json` 은 없앴다.
  - **테이블**: 7개(`app_user`, `word`, `setting`, `study_log`, `exam_session`, `exam_item`, `wrong_word`).
  - **위치**: 환경변수 `DB_PATH`, 없으면 `userdata/voca.db`.
  - **처음 실행**: 빈 DB 면 테이블을 만들고 기본 단어장(2,109개)을 처음 한 번만 넣는다. `PRAGMA user_version` 으로 판단하므로, 단어를 모두 지운 뒤 다시 켜도 되살아나지 않는다.
  - **연결**: `AppSession` 은 메서드마다 연결을 열고 한 트랜잭션으로 끝낸다.
  - **단어 기록의 키**: 영단어(ADR-07)에서 `word.id` 로 바뀌었다. 이력에는 영단어 글자도 함께 남긴다. 그래서 단어를 지워도 통계가 유지된다(`word_id` 만 NULL 이 된다).
  - **정합화**: 손상 파일 보존·정합화(ADR-13)는 DB 외래 키(삭제 시 CASCADE / SET NULL)로 대신한다.
  - **사용자**: 모든 기록에 `user_id`(기본 1)를 둔다. 나중에 로그인을 붙이면 계정별로 나눌 수 있다.

### ADR-26 일차 상태를 단어 단위 이력에서 계산

- **배경**: 하루 학습량을 설정으로 바꿀 수 있고(VOCA-FR-011, 061), 단어를 더하고 지울 수 있게 되었다(VOCA-FR-001·002). 일차 번호별로 완료 플래그를 저장하면 일차 구성이 바뀌는 순간 어긋난다.
- **대안**: (a) 일차별 플래그를 저장하고 구성이 바뀌면 초기화, (b) 일차 상태를 저장하지 않고 단어 이력에서 계산.
- **결정 근거**: **(b).** 두 상태를 이렇게 정의한다.
  - **암기 완료**: 그 일차의 모든 단어에 암기 이력(`study_log`)이 있다.
  - **완료**: 그 일차의 모든 단어가 일차 시험 문항(`exam_item`, 시험 종류 `day`)에 나온 적이 있다.

  이렇게 하면 학습량을 바꿔도 외운 단어는 외운 것으로 남는다.
- **영향**:
  - 계산은 `core/schedule.py` 의 `day_status(일차 단어, 외운 단어 번호들, 시험 본 단어 번호들)` 가 한다.
  - 단어를 더하면 마지막 일차가 다시 "학습 전"이 될 수 있다. 새 단어를 아직 안 봤으므로 맞는 표시다.
  - 실력 시험·오답 시험은 일차를 완료하지 않는다.
  - 다시 학습(복습)해도 암기 이력을 남긴다. "언제 몇 번 외웠는지"가 곧 이력이다.

### ADR-27 시험 형식·방향과 가중 출제

- **배경**: 대상 요구사항은 VOCA-FR-021(문제 수), 022(안 본·오래된·자주 틀린 단어 우선), 023(영→한·한→영·섞기), 024(형식 2가지 이상)다.
- **대안**: 형식 — (a) 4지선다 + 단답형, (b) 4지선다 + 단답형 + OX. 출제 — (c) 균등 무작위, (d) 가중 무작위.
- **결정 근거**: **(b) + (d).**
  - **OX**: 보기 하나를 보여 주고 맞는 짝인지 고른다. 4지선다 화면을 그대로 쓴다. 절반은 맞는 짝, 절반은 다른 뜻·단어를 보여 준다.
  - **섞기**: 문제마다 방향을 무작위로 정한다.
  - **단답형 채점(한→영)**: 대소문자와 앞뒤 공백을 무시하고 영단어와 같으면 정답.
  - **단답형 채점(영→한)**: 뜻 칸을 품사 표시(`[명]`)·쉼표·세미콜론으로 나눈 조각 중 하나와 같거나, 뜻 칸 전체와 같으면 정답. 띄어쓰기와 괄호는 무시한다.
  - **가중치**: `1 + 3·(시험 본 적 없음) + min(마지막 시험 뒤 지난 날, 30)/10 + 2·min(누적 오답, 5)`. 가중치에 비례해 비복원 추출한다(Efraimidis–Spirakis).
  - **재현성**: 난수는 주입한 `random.Random` 만 쓰므로 같은 시드에서 같은 결과가 나온다(NFR-04).
- **영향**:
  - 시험은 세 종류다.
    - 일차 시험: 그 일차 단어 전부.
    - 오답 시험: 오답 목록 전부.
    - 실력 시험: 문제 수를 지정한다. 외운 단어에서 가중 출제하고, 외운 단어가 없으면 전체에서 뽑는다.
  - 시험을 시작하기 전에 시험 설정 화면(S-09)에서 방향·형식을 고른다. 실력 시험은 문제 수도 고른다.
  - 한→영 4지선다는 뜻이 같은 다른 단어를 보기에서 뺀다(ADR-04 의 취지 유지).
  - 문항마다 형식·방향·정오·시각을 `exam_item` 에 남긴다(VOCA-FR-026).

### ADR-28 CSV 가져오기의 중복 처리 (ADR-03 확장)

- **배경**: VOCA-FR-003 은 제공 CSV(`영단어,뜻`, 2,000개)를 일괄 등록하고, 중복 단어를 어떻게 처리할지 직접 정해 문서에 적으라고 한다. 기존 ADR-03 에는 "단어장 바꾸기 + 기록 초기화"만 있었다.
- **대안**: (a) 바꾸기만, (b) 추가만, (c) 확인 화면에서 추가/바꾸기 중 고름.
- **결정 근거**: **(c).**
  - **헤더**: `word,meaning` 과 `영단어,뜻` 둘 다 받는다. UTF-8 BOM 이 있든 없든 읽고, UTF-8 로 안 읽히면 CP949 로 읽는다.
  - **추가**: 이미 있는 영단어(대소문자 무시)는 건너뛰고 기존 뜻을 유지한다. 공부 중인 단어의 뜻이 몰래 바뀌지 않게 하기 위해서다.
  - **파일 안의 중복**: 겹치는 줄은 첫 줄만 쓰고, 건너뛴 줄 번호를 알려 준다.
  - **바꾸기**: 단어와 모든 학습 기록을 지우고 새로 시작한다. ADR-03 과 같은 확인 대화상자를 띄우고, 설정은 유지한다.
- **영향**:
  - 열 개수·빈 칸·길이 위반이 하나라도 있으면 아무것도 넣지 않는다(일부만 들어가는 일 방지).
  - 올린 파일은 디스크에 쓰지 않고 메모리에서 읽는다. 서버에서는 `/data`·`/tmp` 만 쓸 수 있기 때문이다.
  - 확인 화면의 기본 초점은 `추가` 다.
  - 바꾸기를 하면 모든 브라우저에서 진행 중인 카드·시험을 지운다.

### ADR-29 학교 서버 배포 방식 (ADR-18 의 "127.0.0.1 전용" 변경)

- **배경**: 과제는 리포 루트의 `Dockerfile` 로 학교 서버에 올리라고 요구한다(VOCA-SUB-031~037, Dockerfile 구성 R-01~R-16). 컨테이너 조건은 다음과 같다.
  - `0.0.0.0:8080` 에서 듣고, UID 10001 로 실행한다. 리눅스 권한은 없다.
  - 쓰기는 `/data`·`/tmp` 만 된다.
  - 실행 중에는 인터넷을 쓸 수 없다.
  - 앞단 프록시가 `/2026/voca-<학번>/` 아래로 옮겨 준다.
- **대안**: 서버 — (a) gunicorn, (b) Flask 개발 서버. 워커 — (c) 여러 개, (d) 1개.
- **결정 근거**: **(a) + (d).**
  - **서버**: R-14 가 운영 서버를 요구한다.
  - **워커 1개**: 진행 중인 카드·시험은 서버 메모리에 있다(ADR-30). 워커가 여럿이면 요청마다 다른 워커가 받아 상태를 잃는다. 시연 규모에는 sync 워커 1개로 충분하다.
  - **이미지**: `python:3.12-slim`. 의존성(`requirements.txt`, Flask·gunicorn 버전 고정)을 소스보다 먼저 설치하고, `.pyc` 를 쓰지 않는다(`PYTHONDONTWRITEBYTECODE`).
  - **진입점**: `smartvoca.web.wsgi:app`.
  - **세션 키**: `SECRET_KEY`. 없으면 기동할 때 무작위로 만든다.
- **영향**:
  - NFR-02 를 고친다.
    - 로컬 실행(`python -m smartvoca`)은 그대로 127.0.0.1 + 브라우저 자동 열기다. 서버는 werkzeug 를 쓴다(gunicorn 은 Windows 에서 돌지 않는다).
    - 서버 배포는 컨테이너 안에서 0.0.0.0:8080 이다.
  - 주소는 모두 `url_for` 로 `/` 시작 경로를 만들고, HTML 속성은 따옴표로 감싼다(R-04). 앞부분은 서버가 붙여 준다.
  - 점검 워크플로 `.github/workflows/docker-check.yml` 은 배포받은 그대로 둔다(R-09).
  - 규칙 위반은 `tests/test_deploy.py` 가 미리 검사한다.

### ADR-30 화면 상태를 브라우저마다 분리 (ADR-20 대체)

- **배경**: 문제가 두 가지다.
  - 학교 서버에는 여러 사람이 접속한다. 진행 상태가 서버에 하나뿐이면 다른 사람의 카드·시험이 섞인다.
  - 앞단 프록시가 https 로 받아 앱에는 http 로 넘긴다. 그래서 Origin 전체 비교나 Host 허용 목록(127.0.0.1)이 정상 요청까지 막는다.
- **대안**: 상태 — (a) 쿠키의 무작위 ID 별 `WebState`, (b) 로그인 후 계정별. 출처 검사 — (c) 주소 전체 비교, (d) 호스트만 비교.
- **결정 근거**: **(a) + (d).**
  - 로그인이 없어도 브라우저마다 진행이 분리된다.
  - 쿠키에는 ID 만 서명해 두고, 시험지·정답은 서버에만 둔다(ADR-20 의 이유 유지).
  - 학습 기록은 기본 사용자(user_id=1) 하나에 쌓인다. 로그인을 붙이면 계정별로 나뉜다.
- **영향**:
  - `web/state.py` 의 `StateStore` 가 최근에 쓴 상태 500개까지 두고, 오래된 것부터 지운다.
  - 화면 코드는 `web/common.py` 의 `web_state()` 로 상태를 얻는다.
  - Host 허용 목록을 없앴다. POST 의 Origin/Referer 는 호스트 부분만 비교한다.
  - 쿠키는 `SameSite=Lax` 다.

### ADR-31 문서 이름에 버전 표기 (2026-11-18 결정 변경)

- **배경**: 2026-11-18 에 "파일명에 버전을 넣지 않는다(참조가 깨지지 않게)"고 정했다(CLAUDE.md 문서 관리 규칙 2). 그런데 기말 과제(소프트웨어 요건 §4.2)는 `docs/` 산출물 이름을 방법론의 네이밍 규칙 `분류_yymmdd_제목 vX.X.md` 로 하라고 요구한다.
- **대안**: (a) 기존 규칙 유지, (b) 과제 규칙을 따름.
- **결정 근거**: **(b).** 제출 요건이라 평가 대상이므로 2026-11-18 결정을 뒤집는다.
- **영향**:
  - `docs/` 문서 이름 끝에 현재 버전을 붙인다(예: `설계_261111_결정 기록 v1.6.md`).
  - 버전을 올리면 `git mv` 로 이름을 바꾸고, 다른 문서·README·CLAUDE.md 의 참조를 같은 커밋에서 고친다.
  - 헤더의 `**버전**` 과 변경 이력 표는 그대로 쓴다.
  - CLAUDE.md 문서 관리 규칙 2 를 함께 고친다.
