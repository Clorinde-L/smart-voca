## 2. 결정 기록

### 2.1 DD-01 학습 기록 저장 형식

- **배경**: 기획서 §7 에서 JSON / SQLite 선택을 설계 단계로 넘겼다. 저장 대상은 일차 최대 100여 건, 단어 기록 최대 2,000건 수준이다.
- **대안**: (a) JSON 파일 1개, (b) SQLite DB 파일, (c) 기록 종류별 CSV 여러 개.
- **결정 근거**: **(a) JSON 채택.**
  - 데이터가 작아 매번 전체를 다시 써도 부담이 없다(수십 KB 이하).
  - 메모장으로 열어 내용을 바로 확인·수정할 수 있어 디버깅과 학습에 유리하다.
  - 표준 라이브러리 `json` 만 쓰고 스키마·쿼리 코드가 필요 없다.
  - SQLite 의 장점인 트랜잭션은 "임시 파일에 쓰고 교체"(§5.3)로 대신한다.
  - (c) 는 파일 사이 정합성을 따로 맞춰야 해서 제외했다.
- **재검토 조건**: 시험 응시 이력(회차별 점수·답안)을 쌓거나 통계 화면(기획서 §10.2)을 만들게 되면 SQLite 로 옮긴다. 이를 위해 기록에 `schema_version` 을 둔다.

### 2.2 DD-02 사용자 데이터 위치

- **배경**: 학습 기록과 불러온 단어장 사본을 둘 곳이 필요하다. 프로그램은 기본 CSV 와 사용자의 원본 CSV 를 덮어쓰지 않는다(NFR-06).
- **대안**: (a) 프로젝트 루트의 `userdata/`, (b) `%APPDATA%\smart-voca\`, (c) `data/` 안에 함께 저장.
- **결정 근거**: **(a) 채택.** 소스에서 직접 실행하는 프로젝트라 프로젝트 폴더 안에 있어야 찾고 지우기 쉽다. (c) 는 커밋되는 기준 데이터와 개인 기록이 섞인다. (b) 는 exe 로 배포할 때 맞는 위치이므로, 배포 방식이 정해지면 다시 검토한다. 저장소 코드는 기준 디렉토리를 인자로 받아 위치가 바뀌어도 로직이 바뀌지 않게 한다.
- **부수 조치**: `userdata/` 를 `.gitignore` 에 추가한다(구현 단계).

### 2.3 DD-03 단어 기록의 키

- **배경**: 단어별 기록을 단어장의 어느 값에 묶을지 정해야 한다.
- **대안**: (a) 영단어 문자열, (b) 단어장 내 순번.
- **결정 근거**: **(a) 채택.** 영단어는 단어장 안에서 유일하다(FR-02). 기본 단어장의 뜻을 검수해 고치거나 줄 순서가 바뀌어도 기록이 다른 단어에 붙지 않는다. 기록 파일을 사람이 읽기도 쉽다.

## 3. 논리 데이터 모델

### 3.1 엔터티 관계

```
단어장 (Wordbook) 1 ──── N 단어 (Word)
   │                         │ 1
   │ 20개씩 순서대로 분할        │
   ▼                         ▼ 0..1
일차 (Day) [파생]            단어 기록 (WordRecord)
   │ 1                            ▲
   ▼ 0..1                         │ N
일차 기록 (DayRecord) N ── 1 학습 기록 (Progress) 1
```

- **저장하는 것**: 단어(CSV), 일차 기록·단어 기록(JSON).
- **저장하지 않는 것**: 일차(단어장에서 매번 계산), 시험지·답안·채점 결과(시험 중에만 메모리에 존재).

### 3.2 엔터티 정의

**단어 (Word)** — 단어장 CSV 의 한 줄

| 속성 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `index` | 정수 | 0 부터, 단어장 내 유일 | 단어장 순번. 파일에는 없고 읽을 때 붙인다 |
| `word` | 문자열 | 비어 있지 않음, 대소문자 무시 유일 | 영단어. 단어 기록의 키 |
| `meaning` | 문자열 | 비어 있지 않음 | 뜻 칸 원문. 가공하지 않는다 |

**일차 (Day)** — 파생 엔터티, 저장하지 않음

| 속성 | 타입 | 설명 |
|------|------|------|
| `day_no` | 정수 | 1 부터 |
| `start`, `end` | 정수 | 단어 순번 범위 `[start, end)`. `start = (day_no - 1) × 20` |
| 상태 | 열거 | `잠김 / 학습 가능 / 암기 완료 / 완료`. 일차 기록에서 계산(프로세스 설계서) |

**일차 기록 (DayRecord)** — 상태가 생긴 일차만 저장

| 속성 | 타입 | 기본값 | 설명 | 대응 FR |
|------|------|--------|------|---------|
| `day_no` | 정수 | — | 1 ≤ `day_no` ≤ 전체 일차 수 | FR-08 |
| `memorized` | 불리언 | `false` | 암기 완료 여부 | FR-12 |
| `tested` | 불리언 | `false` | 시험 제출 여부(일차 완료). `true` 이면 `memorized` 도 `true` | FR-18 |

**단어 기록 (WordRecord)** — 한 번이라도 틀린 단어만 저장

| 속성 | 타입 | 기본값 | 설명 | 대응 FR |
|------|------|--------|------|---------|
| `word` | 문자열 | — | 영단어(키) | — |
| `wrong_count` | 정수 | 0 | 누적 오답 횟수. 1 이상. 목록에서 빠져도 유지 | FR-17, FR-25 |
| `streak` | 정수 | 0 | 오답 시험 연속 정답 횟수. 0~2. 3 이 되는 순간 목록에서 빠지고 0 이 된다 | FR-25 |
| `in_wrong_list` | 불리언 | `false` | 오답 목록 등재 여부 | FR-17, FR-22 |

**학습 기록 (Progress)** — 기록 파일 전체

| 속성 | 타입 | 설명 |
|------|------|------|
| `schema_version` | 정수 | 기록 형식 버전. 현재 `1` |
| `saved_at` | 문자열 | 마지막 저장 시각(ISO 8601, 로컬 시간). 확인용이며 로직에 쓰지 않는다 |
| `days` | 일차 기록 모음 | `day_no` 로 찾는다 |
| `words` | 단어 기록 모음 | `word` 로 찾는다 |

> "현재 일차"는 저장하지 않는다. `tested` 가 `false` 인 가장 작은 일차로 계산한다. 값을 따로 저장하면 일차 기록과 어긋날 수 있기 때문이다.

## 4. 물리 설계 — 파일

### 4.1 파일 목록

| 파일 | 형식 | 쓰는 주체 | 커밋 | 설명 |
|------|------|-----------|------|------|
| `data/toeic_words_2000.csv` | CSV | `build_csv.py` (프로그램은 읽기만) | O | 기본 단어장 |
| `userdata/wordbook.csv` | CSV | 프로그램 | X | 사용자가 불러온 단어장의 사본. 없으면 기본 단어장을 쓴다 |
| `userdata/progress.json` | JSON | 프로그램 | X | 학습 기록 |
| `userdata/progress.json.tmp` | JSON | 프로그램 | X | 저장 중 임시 파일(§5.3) |
| `userdata/progress.corrupt-YYYYMMDD-HHMMSS.json` | — | 프로그램 | X | 읽지 못한 기록의 보존본(FR-28) |
| `userdata/wordbook.invalid-YYYYMMDD-HHMMSS.csv` | — | 프로그램 | X | 검증에 실패한 단어장 사본의 보존본(§6.3) |
| 사용자가 지정한 경로 | CSV | 프로그램 | — | 단어장·오답 목록 내보내기 결과 |

### 4.2 단어장 CSV (`toeic_words_2000.csv`, `wordbook.csv`, 단어장 내보내기)

| 항목 | 규격 |
|------|------|
| 인코딩 | 쓰기 `utf-8-sig`. 읽기 `utf-8-sig`(BOM 이 없어도 읽힌다) |
| 헤더 | `word,meaning` |
| 행 | 영단어 1개, 뜻 칸 1개. 쉼표·큰따옴표가 든 값은 CSV 규칙대로 큰따옴표로 감싼다 |
| 줄바꿈 | 쓰기 `\r\n` (`csv` 모듈 기본값). 읽기는 가리지 않는다 |
| 순서 | 파일의 줄 순서가 단어 순번이자 일차 순서 |

### 4.3 오답 목록 CSV (내보내기 전용, FR-06)

| 항목 | 규격 |
|------|------|
| 인코딩·줄바꿈 | 단어장 CSV 와 같다 |
| 헤더 | `word,meaning,wrong_count` |
| 순서 | 오답 횟수 내림차순, 같으면 단어장 순서(FR-22) |

앞의 두 열이 단어장 CSV 와 같아서, `wrong_count` 열만 지우면 단어장으로 다시 불러올 수 있다.

### 4.4 학습 기록 JSON (`progress.json`)

| 항목 | 규격 |
|------|------|
| 인코딩 | `utf-8` (BOM 없음) |
| 표기 | 들여쓰기 2칸, 한글·특수문자를 이스케이프하지 않음(`ensure_ascii=False`) |

```json
{
  "schema_version": 1,
  "saved_at": "2026-11-11T14:30:00",
  "days": {
    "1": { "memorized": true, "tested": true },
    "2": { "memorized": true, "tested": false }
  },
  "words": {
    "accommodate": { "wrong_count": 2, "streak": 1, "in_wrong_list": true },
    "agenda": { "wrong_count": 1, "streak": 0, "in_wrong_list": false }
  }
}
```

| 키 | 타입 | 제약 |
|----|------|------|
| `schema_version` | 정수 | `1` |
| `saved_at` | 문자열 | ISO 8601 |
| `days` | 객체 | 키는 일차 번호의 문자열(JSON 객체의 키는 문자열만 가능). 값은 `memorized`, `tested` 불리언 |
| `words` | 객체 | 키는 영단어 원문. 값은 `wrong_count`(정수 ≥ 1), `streak`(정수 0~2), `in_wrong_list`(불리언) |

- 초기 상태는 `days` 와 `words` 가 빈 객체다. 파일이 없는 것과 같은 뜻이다.
- 위 예시에서 3일차 이후는 기록이 없으므로 잠김이고, 2일차는 암기 완료(시험 대기)다.

## 5. 저장소 정책

### 5.1 저장 시점 (FR-26)

| 사건 | 바뀌는 데이터 |
|------|----------------|
| 일차 암기 완료 | `days[n].memorized` |
| 일차 시험 제출 | `days[n].tested`, 틀린 단어의 `words[w]` |
| 오답 시험 제출 | 대상 단어의 `words[w]` |
| 단어장 교체 | `wordbook.csv` 교체 후 `progress.json` 초기화 |

사건마다 `progress.json` 전체를 다시 쓴다.

### 5.2 읽는 시점

프로그램을 시작할 때 한 번 읽고, 이후에는 메모리의 학습 기록을 기준으로 삼는다.

### 5.3 안전한 쓰기 (NFR-06)

1. 같은 폴더의 임시 파일(`progress.json.tmp`)에 전체 내용을 쓴다.
2. 디스크에 내려 쓴 뒤(flush, fsync) 닫는다.
3. `os.replace` 로 임시 파일을 `progress.json` 으로 바꾼다.

쓰는 도중 프로그램이 꺼지면 임시 파일만 불완전하고 `progress.json` 은 직전 내용 그대로다. `wordbook.csv` 도 같은 방식으로 쓴다. 남아 있는 `.tmp` 파일은 다음 저장 때 덮어쓴다.

### 5.4 단어장 교체 순서 (FR-03, FR-04)

1. 사용자가 고른 CSV 를 읽고 검증한다(§6). 실패하면 여기서 끝나고 아무것도 바뀌지 않는다.
2. 사용자 확인을 받는다. 취소하면 끝난다.
3. 검증된 단어 목록을 `userdata/wordbook.csv` 로 쓴다(§5.3).
4. 학습 기록을 초기 상태로 만들어 저장한다.

3과 4 사이에 프로그램이 꺼지면 새 단어장에 옛 기록이 남는데, 다음 실행 때 §5.5 의 정합화가 맞지 않는 항목을 걸러 낸다.

기본 단어장으로 되돌리려면 `data/toeic_words_2000.csv` 를 불러오면 된다.

### 5.5 복원 시 정합화 (FR-27)

기록은 읽혔지만 현재 단어장과 맞지 않는 항목이 있으면 아래처럼 고쳐서 쓴다. 기본 단어장의 뜻을 검수해 고치거나 단어를 몇 개 바꾼 경우에도 나머지 기록을 살리기 위한 규칙이다.

| 상황 | 처리 |
|------|------|
| `words` 의 키가 현재 단어장에 없음 | 그 단어 기록을 버린다 |
| `days` 의 번호가 전체 일차 수보다 큼 | 그 일차 기록을 버린다 |
| `tested` 가 `true` 인데 `memorized` 가 `false` | `memorized` 를 `true` 로 고친다 |
| `in_wrong_list` 가 `false` 인데 `streak` 이 0 이 아님 | `streak` 을 0 으로 고친다 |

고친 내용은 다음 저장 때 파일에 반영된다.

### 5.6 손상 판정 (FR-28)

아래 중 하나면 손상으로 본다. 파일을 `progress.corrupt-YYYYMMDD-HHMMSS.json` 으로 이름을 바꿔 보존하고 초기 상태로 시작하며 사용자에게 알린다.

- JSON 으로 해석되지 않는다.
- 최상위가 객체가 아니거나 `days`, `words` 가 객체가 아니다.
- `schema_version` 이 `1` 이 아니다.
- 값의 타입이나 범위가 §4.4 의 제약을 벗어난다(예: `wrong_count` 가 음수, `streak` 이 3 이상, 일차 키가 숫자가 아님).

## 6. 단어장 검증 규칙 (FR-02)

### 6.1 규칙

| ID | 검사 | 실패 시 메시지에 담을 내용 |
|----|------|-----------------------------|
| V-01 | 파일을 열 수 있고 UTF-8 로 해석된다 | 파일 경로, 인코딩 안내("UTF-8 로 저장해 주세요") |
| V-02 | 첫 줄이 `word,meaning` 이다. 앞뒤 공백과 대소문자 차이는 허용한다 | 실제 헤더 |
| V-03 | 모든 행의 열이 정확히 2개다 | 행 번호, 열 개수 |
| V-04 | `word`, `meaning` 이 앞뒤 공백을 떼고도 비어 있지 않다 | 행 번호, 빈 열 이름 |
| V-05 | `word` 가 대소문자를 무시하고 중복되지 않는다 | 행 번호, 단어, 먼저 나온 행 번호 |
| V-06 | 단어가 4개 이상이다 | 단어 수 |
| V-07 | 서로 다른 `meaning` 이 4개 이상이다 | 서로 다른 뜻의 수 |

### 6.2 처리 원칙

- 행 번호는 파일의 줄 번호(헤더가 1)로 알려 준다. 사용자가 엑셀·메모장에서 바로 찾을 수 있게 하기 위함이다.
- 아무 내용이 없는 빈 줄은 건너뛴다. 오류로 보지 않는다.
- `word`, `meaning` 의 앞뒤 공백은 떼고 읽는다. 그 밖의 내용은 바꾸지 않는다.
- V-01, V-02 에 실패하면 바로 멈춘다. V-03~V-05 는 끝까지 검사해 위반을 모아서 알려 주되, 화면에는 처음 20건과 전체 건수를 보여 준다. V-06, V-07 은 앞의 검사에서 위반이 없을 때만 검사한다.
- 위반이 하나라도 있으면 단어장을 바꾸지 않는다.

### 6.3 시작할 때의 검증

시작할 때 읽는 단어장에도 같은 규칙을 적용한다.

| 상황 | 처리 |
|------|------|
| `userdata/wordbook.csv` 가 검증에 실패 | 파일을 `wordbook.invalid-YYYYMMDD-HHMMSS.csv` 로 보존하고 기본 단어장으로 시작한다. 사용자에게 알린다. 기록은 §5.5 로 정합화한다 |
| 기본 단어장이 없거나 검증에 실패 | 프로그램을 계속할 수 없다. 원인을 알리고 종료한다 |
