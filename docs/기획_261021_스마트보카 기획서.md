## 2. 추진 배경 및 문제 정의

### 2.1 배경
- 토익은 대학생의 졸업 요건과 취업 준비에 널리 쓰이는 시험이고, 점수를 올리는 데는 어휘력이 기본이 된다.
- 종이 단어장이나 일반 단어장 앱은 **매일 얼마만큼 외울지**, **무엇을 다시 볼지**를 학습자가 직접 정해야 한다.

### 2.2 해결하려는 문제

| ID | 문제 |
|----|------|
| P-01 | 하루 학습량을 스스로 나누고 관리하기 번거로워 꾸준히 이어 가기 어렵다. |
| P-02 | 이미 외운 단어를 다시 보지 않아 쉽게 잊는다. |
| P-03 | 자주 틀리는 단어(취약 단어)를 따로 관리하지 않아 같은 실수를 반복한다. |
| P-04 | 외운 뒤 바로 확인하는 시험이 없어 실제로 외웠는지 알기 어렵다. |

## 6. 핵심 기능 및 학습 흐름

### 6.1 전체 흐름

```
[브라우저로 접속] → [DB 준비 (처음이면 기본 단어장 등록)] → [메인 화면]
   ├─ 일차 학습: [오늘의 학습 또는 고른 일차] → [암기: 1개씩 카드 넘기기 + 복습 카드 몇 장] → (모두 봄)
   │             → [시험 설정: 방향·형식] → [시험 응시·채점] → [문항 이력·오답 기록] → [다음 추천 일차]
   ├─ 복습 학습: [일차 목록에서 끝낸 일차 선택] → [암기 카드로 다시 보기]
   ├─ 오답 학습: [오답 단어 목록(오답 횟수 많은 순)] → [암기 카드로 다시 보기]
   │             → [오답 시험] → (연속 3회 정답이면 오답 목록에서 제외)
   ├─ 실력 시험: [문제 수·방향·형식] → [외운 단어에서 가중 출제] → [채점·이력]
   ├─ 통계: 진도, 정답률 추이, 자주 틀리는 단어
   ├─ 단어 관리: 등록·수정·삭제·검색, CSV 가져오기(추가/바꾸기)·내보내기
   └─ 설정: 하루 학습량, 복습 카드 수, 시험 기본값

(v1.8. 2026-11-25 부터 일차 잠금이 없어 아무 일차나 고를 수 있다 — ADR-21)
```

### 6.2 진도 생성 규칙 (SC-03)

| 구분 | 규칙 |
|------|------|
| 배정 방식 | 단어장 순서대로 일차마다 신규 단어를 **하루 학습량(기본 20개)씩** 배정한다. v1.8: 설정에서 5~100 으로 바꿀 수 있다 |
| 중복 금지 | 한 단어는 한 일차에만 속한다. 일차 사이에 같은 단어가 나오지 않는다 |
| 일차 수 | 기본값으로 2,109개 ÷ 20 = **106일차**(마지막 106일차는 9개). 나누어떨어지지 않으면 마지막 일차는 남은 단어로 구성한다 |
| 복습·오답 | 일차 배정에는 섞지 않는다. v1.8: 카드 학습 끝에만 복습 카드(전날 외운 단어 + 자주 틀린 단어, 기본 4장)를 덧붙인다(§6.5). 기록상 그날 단어와 구분된다 |

- 예시(기본값): 1일차는 1~20번 단어, 2일차는 21~40번 단어 … 105일차는 2,081~2,100번, 106일차는 2,101~2,109번 단어.
- 일차 상태(학습 전 / 암기 완료 / 완료)는 저장하지 않고 단어 이력에서 계산한다. 그래서 하루 학습량을 바꾸거나 단어를 더해도 외운 단어는 외운 것으로 남는다(ADR-26).

### 6.3 일차 학습 – 암기 (SC-04)
- 한 화면에 단어 카드 1장(영단어와 그 뜻)을 보여 주고 '다음' / '이전'으로 넘긴다.
- 뜻은 CSV 뜻 칸의 내용을 **가공하지 않고 그대로** 보여 준다. 예를 들어 뜻 칸이 '문제, 쟁점; 발행하다'이면 전부 보여 준다.
- 그 일차의 단어를 모두 한 번씩 보면 '암기 완료'로 표시하고 시험 버튼을 활성화한다. 본 카드마다 암기 이력(언제, 어느 단어)을 남긴다(VOCA-FR-014).
- 하루에 여러 일차를 진행해도 된다. 실제 날짜가 아니라 **완료 여부**로 다음 일차를 추천한다.

### 6.4 시험 (SC-05)
- 시험 범위: 일차 시험은 해당 일차의 단어 전부. v1.8 실력 시험은 문제 수를 정하고, 외운 단어 중 안 본 단어·오래된 단어·자주 틀린 단어를 더 자주 낸다(VOCA-FR-021, 022).
- v1.8 출제 방향: 영→한 / 한→영 / 섞기. 형식: 4지선다 / 단답형 / OX. 시험을 시작하기 전에 고른다(VOCA-FR-023, 024, ADR-27).
  - 단답형 영→한은 뜻 칸의 뜻 가운데 하나만 적어도 정답이다(띄어쓰기 무시). 한→영은 철자가 같아야 한다(대소문자 무시).
- 4지선다 영→한은 영단어를 보여 주고 뜻을 4개 보기 중에서 고른다(v1.7 까지의 유일한 형식):
  - 정답 보기와 오답 보기 모두 CSV 뜻 칸 전체를 그대로 쓴다. 오답 보기 3개는 전체 단어장에서 다른 단어의 뜻 칸을 무작위로 뽑는다.
  - 뜻이 길면 보기 문장도 길어지므로, 보기가 잘리지 않도록 UI에서 줄바꿈을 지원한다.
  - 문제 순서는 무작위로 섞는다.
- 채점 결과(맞은 수 / 전체, 틀린 문항과 정답)를 보여 주고, 틀린 단어는 오답 횟수를 +1 하고 오답 목록에 올린다. 문항마다 형식·방향·정오·시각을 이력으로 남긴다(VOCA-FR-025, 026).
- 점수와 관계없이 일차 시험을 마치면 그 일차를 '완료'로 표시한다.
- 이미 완료한 일차의 시험도 다시 볼 수 있다. 재시험에서 틀린 단어도 오답 목록에 올린다.

### 6.5 복습 학습 (SC-06)
- 이미 학습한 일차 중에서 하나를 골라 그 일차의 단어를 암기 카드 방식으로 다시 본다.
- 일차 진도(현재 일차, 완료 여부)에는 영향을 주지 않는다. 암기 이력은 남는다.
- v1.8: 일차 학습의 끝에 복습 카드를 설정한 수(기본 4장)만큼 덧붙인다. 절반은 전날 외운 단어, 나머지는 자주 틀린 단어다(VOCA-FR-013).
- 복습 학습에는 별도 시험을 두지 않는다. 지난 일차를 시험 보고 싶으면 일차 시험을 다시 보면 된다(§6.4).

### 6.6 오답 학습 (SC-07)
- 지금까지 시험에서 틀린 단어를 모아 오답 횟수가 많은 순서대로 암기 카드 방식으로 보여 준다.
- 오답 학습을 마치면 오답 단어로 **오답 시험**을 볼 수 있다. 문제 형식은 일차 시험과 같다.
- 단어마다 **연속 정답 횟수**를 기록한다.
  - 맞히면 연속 정답 횟수를 1 늘리고, **3이 되면 오답 목록에서 뺀다.**
  - 틀리면 연속 정답 횟수를 0으로 되돌리고 오답 횟수를 1 늘린다.
  - 일차 시험에서 다시 틀리면 그 단어는 오답 목록에 다시 올라간다.
- 오답 목록은 CSV로 내보낼 수 있다 (BR-06).

### 6.7 단어 관리·가져오기·내보내기 (SC-01, SC-09)
- v1.8 **단어 관리**: 단어를 직접 등록하고, 목록에서 검색(영단어·뜻·일차)·수정·삭제한다(VOCA-FR-001 ~ 004). 고쳐도 그 단어의 기록이 이어진다.
- **가져오기**: 사용자가 고른 CSV(`영단어,뜻` 또는 `word,meaning` 헤더, 과제 제공 CSV 2,000개 포함)를 읽어 들인다. 확인 화면에서 둘 중 하나를 고른다(ADR-28).
  - **추가**: 이미 있는 단어는 건너뛰고 지금 뜻을 유지한다.
  - **바꾸기**: 단어와 학습 기록을 모두 지우고 새로 시작한다.
- **내보내기**: 현재 단어장과 오답 목록을 각각 CSV로 내려받는다.

### 6.8 학습 통계 (SC-10, v1.8)
- 진도 현황: 현재 일차, 외운 단어 수 / 전체, 완료한 일차, 전체 정답률(VOCA-FR-031).
- 시험 성적 추이: 회차별·날짜별 정답률 막대 그래프와 표(VOCA-FR-032).
- 자주 틀리는 단어 상위 10개(VOCA-FR-033).
- 모든 값은 DB 이력에서 그때그때 계산한다(VOCA-FR-034).

## 8. 기술 스택 후보 및 결정 (결정 기록)

### 8.1 배경
요청 내용상 Windows에서 개발한다는 점은 정해져 있다. 하지만 결과물을 **Windows 데스크톱 프로그램(Python/PyQt)** 과 **Android 앱(Kotlin)** 중 무엇으로 할지는 아직 정해지지 않았다.

### 8.2 대안 비교

| 항목 | A. Python + PyQt (Windows) | B. Kotlin (Android) |
|------|----------------------------|---------------------|
| 개발 환경 구성 | 쉬움 (Python, `pip install PyQt6`) | Android Studio, SDK, 에뮬레이터가 필요해 무거움 |
| CSV 처리 | 표준 라이브러리 `csv`로 간단함 | assets와 파일 접근 권한 처리가 필요함 |
| 파일 불러오기·저장(BR-06) | `QFileDialog`로 바로 구현 가능 | SAF(Storage Access Framework)를 써야 해서 상대적으로 복잡함 |
| 사용성 | PC 앞에서만 학습 가능 | 이동 중에도 학습 가능 (단어 앱에 더 어울림) |
| 테스트 | `pytest`로 로직을 단위 테스트하기 쉬움 | JUnit과 에뮬레이터가 필요함 |
| 배포 | PyInstaller로 exe 생성 | APK 빌드 |

### 8.3 결정 근거 (권고)
- **권고안: A. Python + PyQt**
  - 진도 생성, 시험 채점, 오답 집계 로직을 Python에서 가장 빠르게 구현하고 검증할 수 있다.
  - 파일 불러오기·저장 요구사항(BR-06)이 데스크톱 환경에서 훨씬 자연스럽다.
  - 로직을 UI와 분리해 두면 나중에 Kotlin으로 옮길 때 로직 설계를 그대로 다시 쓸 수 있다.
- **최종 결정 (2026-10-21)**: **A. Python + PyQt로 Windows 데스크톱 프로그램을 개발한다.** Python과 PyQt의 세부 버전(PyQt5/PyQt6)은 설계 단계의 결정 기록에서 정한다.

### 8.4 웹 전환과 서버 배포 (v1.8 추가)

- **배경**: 2026-11-25 교수님이 웹으로 구현하라고 하셨고, 같은 날 공지된 기말 과제(단어장 웹 앱)는 세 가지를 요구한다.
  - 리포 루트의 `Dockerfile` 로 학교 서버에 올린다.
  - SQLite(`DB_PATH`)를 쓴다.
  - 공개 GitHub 리포로 낸다.
- **결정**:
  - 화면을 PyQt6 데스크톱에서 Flask 웹으로 바꾼다(ADR-18, ADR-19). 로직(`core`)·저장(`storage`)·`AppSession` 계층은 그대로 쓴다. 계층을 나눠 둔 덕분이다(§8.3 근거 3).
  - 서버에서는 컨테이너 안 gunicorn(워커 1개)이 `0.0.0.0:8080` 에서 듣는다. 로컬에서는 `python -m smartvoca` 가 `127.0.0.1:8765` 에 띄우고 브라우저를 연다(ADR-29).
  - 진행 중인 카드·시험은 브라우저마다 따로 서버 메모리에 둔다(ADR-30).
- **기술 스택**:
  - 언어: Python 3.12
  - 화면: Flask 3.1 + Jinja2 템플릿
  - 서버: gunicorn 23
  - 저장: SQLite(`sqlite3` 표준 라이브러리)
  - 테스트: pytest
  - 배포: Docker(`python:3.12-slim`), GitHub Actions 점검 워크플로

§8.1 ~ §8.3 은 기획 당시(2026-10-21)의 결정이며 기록으로 남긴다.
