## 2. 현황 분석

### 2.1 기존 학습 흐름과 문제 지점

대상 사용자(토익을 준비하는 대학생)가 종이 단어장이나 일반 단어장 앱으로 공부할 때의 흐름이다.

| 단계 | 사용자가 하는 일 | 문제 지점 | 관련 문제 |
|------|------------------|-----------|-----------|
| 1. 분량 정하기 | 오늘 외울 범위를 직접 정한다 | 매일 범위를 정하고 어디까지 했는지 기억해야 한다. 하루 밀리면 계획이 흐트러진다 | P-01 |
| 2. 암기 | 단어와 뜻을 훑어본다 | 다 봤는지, 어디서 멈췄는지 기록이 남지 않는다 | P-01 |
| 3. 확인 | 뜻을 가리고 스스로 떠올려 본다 | 스스로 채점하므로 느슨해지고, 결과가 남지 않는다 | P-04 |
| 4. 복습 | 예전 범위를 다시 본다 | 무엇을 다시 볼지 스스로 골라야 해서 대개 건너뛴다 | P-02 |
| 5. 취약 단어 관리 | 틀린 단어에 표시한다 | 표시가 여러 쪽에 흩어져 모아 보기 어렵고, 언제 외웠다고 볼지 기준이 없다 | P-03 |

### 2.2 사용자 기대

- 무엇을 외울지 고민하지 않고 **정해진 진도**를 따라간다 (기획서 §4).
- 외운 직후 **객관적으로 채점**되는 시험으로 확인한다.
- 복습과 오답은 **원할 때 따로** 챙긴다. 일차 분량에 섞여 하루 분량이 늘어나는 것은 원하지 않는다 (기획서 v1.1 결정).

### 2.3 기존 자산

| 자산 | 상태 |
|------|------|
| 기본 단어 데이터 | `data/toeic_words_2000.csv` 2,000 단어 작성 완료. 뜻 내용은 사용자 검수 전 (기획서 §7) |
| 원본·생성 스크립트 | `ai-agent/claude/261021_토익단어2000/data/*.tsv` 11개, `script/build_csv.py` |
| 기존 시스템 | 없음 (신규 개발). 연계할 내부 시스템·데이터 없음 |

### 2.4 가정 및 제약

기획서 §9 와 같다. 단일 사용자, 로컬 저장, Windows 11, Python + PyQt, 오프라인.

## 3. 환경 분석

### 3.1 유사 앱의 학습 흐름

| 항목 | Anki | Quizlet | 클래스카드 | 스마트 보카 |
|------|------|---------|------------|-------------|
| 성격 | 간격 반복(SRS) 플래시카드 | 세트 단위 플래시카드·시험 | 국내 단어 학습 서비스(학교·학원 중심) | 일차 진도형 토익 단어장 |
| 분량 결정 | 알고리즘이 그날 볼 카드를 정함(신규 수·복습 수 설정 필요) | 사용자가 세트를 골라 원하는 만큼 | 세트(단원) 단위로 선택 | **일차당 20개 고정**, 순서대로 진행 |
| 암기 방식 | 카드 앞면을 보고 답을 떠올린 뒤 뒤집기 | 카드 뒤집기, 학습 모드 | 암기·리콜·스펠 단계 학습 | 영단어와 뜻을 함께 보는 카드 넘기기 |
| 확인 방식 | 스스로 난이도 평가(자가 채점) | 객관식·주관식 등 시험 모드 | 테스트, 매칭 게임 | **객관식 4지선다**, 자동 채점 |
| 복습 | 일일 분량에 자동으로 섞임 | 사용자가 직접 다시 학습 | 사용자가 직접 다시 학습 | **별도 메뉴**에서 지난 일차 선택 |
| 오답 관리 | 틀린 카드는 간격이 짧아져 다시 나옴 | 틀린 항목 다시 학습 | 틀린 단어 다시 학습 | **오답 목록 + 오답 시험**, 연속 3회 정답 시 제외 |
| 데이터 | 덱 가져오기·내보내기 | 온라인 세트 | 온라인 세트 | CSV 불러오기·내보내기 |
| 사용 환경 | 데스크톱·모바일, 동기화는 선택 | 웹·모바일, 계정 필요 | 웹·모바일, 계정 필요 | Windows 데스크톱, 오프라인, 계정 없음 |

### 3.2 시사점

| 번호 | 시사점 | 반영 |
|------|--------|------|
| I-01 | Anki 식 SRS 는 복습이 일일 분량에 섞여 분량 예측이 어렵고 초기 설정 부담이 있다. 스마트 보카는 "고민 없이 따라가는 진도"가 목표이므로 **고정 분량 + 복습 분리**가 맞다 | FR-07, FR-20~21. SRS 는 확장 아이디어(기획서 §10.2)로 유지 |
| I-02 | 자가 채점은 결과가 주관적이다. 외웠는지 확인하려면 **자동 채점되는 시험**이 필요하다 | FR-14~16 |
| I-03 | 유사 앱은 틀린 항목을 다시 보여 주지만 "언제 졸업하는가"가 사용자에게 드러나지 않는 경우가 많다. **연속 3회 정답**이라는 눈에 보이는 기준을 화면에 표시하면 동기 부여가 된다 | FR-25. UI/UX 설계서에서 오답 카드에 연속 정답 횟수 표시 검토 |
| I-04 | 카드 뒤집기(뜻 가리기)는 유사 앱의 공통 방식이다. 기획서는 영단어와 뜻을 함께 보여 주는 방식으로 확정했으므로 이번 범위에서는 따르되, 뜻 가리기 옵션은 개선 후보로 남긴다 | FR-10. UI/UX 설계서에서 제안 항목으로 검토 |
| I-05 | 계정·동기화가 없는 대신 기록이 PC 한 대에만 있다. 기록 손상·분실 대비가 중요하다 | FR-28, NFR-06, FR-06 |

### 3.3 기술 환경

| 항목 | 현황 (2026-11-11 개발 PC 확인) | 비고 |
|------|--------------------------------|------|
| OS | Windows 11 Home | 기획서 §9 제약과 일치 |
| Python | 3.12.10 설치됨 | 세부 버전 고정 여부는 결정 기록(#8) |
| PyQt | **미설치** | PyQt5 / PyQt6 선택은 결정 기록(#8). 설치는 사용자 승인 필요 |
| pytest | **미설치** | NFR-04 에 필요. 설치는 사용자 승인 필요 |
| CSV 처리 | 표준 라이브러리 `csv` | `utf-8-sig` 로 BOM 처리. 추가 패키지 불필요 |
| 저장소 후보 | 표준 라이브러리 `json`, `sqlite3`(SQLite 3.49.1 내장) | 둘 다 추가 설치 없이 사용 가능. 선택은 데이터 설계서(#4)·결정 기록(#8) |
| 배포 | PyInstaller 미설치 | exe 배포는 기획서 §8.2 에 후보로만 언급. 필요 여부는 구현 단계에서 결정 |

### 3.4 저장소 후보 비교 (결정 기록 #8 의 입력)

| 항목 | JSON 파일 | SQLite |
|------|-----------|--------|
| 데이터 규모 적합성 | 단어 2,000개·일차 100개 수준이면 충분 | 충분 (여유 큼) |
| 구현 난이도 | 낮음. 딕셔너리를 그대로 읽고 씀 | 중간. 스키마·쿼리 필요 |
| 부분 갱신 | 전체 파일을 다시 씀 (규모가 작아 문제없음) | 행 단위 갱신 |
| 비정상 종료 대비 (NFR-06) | 임시 파일에 쓰고 교체하는 방식으로 직접 처리해야 함 | 트랜잭션으로 기본 제공 |
| 사람이 직접 확인·수정 | 쉬움 (텍스트) | 별도 도구 필요 |
| 테스트 | 임시 디렉토리로 간단 | 메모리 DB 로 간단 |

- **분석 의견**: 저장할 데이터가 작고 구조가 단순해 두 방식 모두 가능하다. 학습 목적과 디버깅 편의를 보면 JSON, 데이터 설계(논리·물리 스키마) 산출물의 충실도를 보면 SQLite 가 유리하다. 최종 선택은 데이터 설계서(#4)에서 한다.

## 4. 결론

- 기존 방식의 문제(P-01~P-04)는 "분량 결정·기록·채점·복습 선택을 모두 사용자가 직접 한다"는 데서 나온다. 스마트 보카는 이를 **고정 진도, 자동 저장, 자동 채점, 분리된 복습·오답 메뉴**로 대신한다.
- 유사 앱과 비교한 차별점은 **설정 없이 바로 따라가는 일차 진도**와 **눈에 보이는 오답 졸업 기준**이다.
- 기술 환경은 Python 표준 라이브러리만으로 데이터·저장소 요구를 충족한다. 추가로 설치할 것은 PyQt 와 pytest 두 가지다.
