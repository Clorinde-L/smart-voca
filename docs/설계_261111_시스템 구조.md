## 2. 계층 구조

```
┌───────────────────────────────────────────────┐
│ UI 계층            smartvoca.web    (Flask)   │  URL·화면 전이, HTML 그리기
└──────────────────────┬────────────────────────┘
                       │ 호출 (한 방향)
┌──────────────────────▼────────────────────────┐
│ 응용 계층          smartvoca.session          │  흐름 조립, 저장 시점 관리
└─────────┬─────────────────────────┬───────────┘
          │                         │
┌─────────▼──────────┐   ┌──────────▼───────────┐
│ 도메인 로직 계층     │   │ 데이터 접근 계층       │
│ smartvoca.core     │◀──│ smartvoca.storage    │
│ 진도·카드·시험·오답   │   │ CSV, progress.json   │
└────────────────────┘   └──────────────────────┘
```

| 계층 | 패키지 | 역할 | 쓸 수 있는 것 |
|------|--------|------|----------------|
| UI | `smartvoca.web` | URL(화면)·폼 처리, 진행 중인 카드·시험 상태(`WebState`), 템플릿·CSS·JS. 학습 규칙(진도·채점·오답)은 갖지 않는다 | `session`, `core.models`(자료형), `core.cards`(`CardDeck`), Flask |
| 응용 | `smartvoca.session` | UI 가 부르는 유일한 창구. 로직 함수를 순서대로 부르고 저장한다 | `core`, `storage` |
| 도메인 로직 | `smartvoca.core` | 프로세스 설계서의 계산·상태 변경 규칙 | 표준 라이브러리만 |
| 데이터 접근 | `smartvoca.storage` | 파일 읽기·쓰기, 검증, 손상 처리 | `core.models`, 표준 라이브러리 |

### 2.1 의존 규칙

| 규칙 | 내용 | 근거 |
|------|------|------|
| R-01 | 호출은 위에서 아래로만 한다. `core`, `storage`, `session` 은 `web` 을 import 하지 않는다 | NFR-03 |
| R-02 | `core`, `storage`, `session` 은 Flask·Werkzeug·Jinja2(와 예전 PyQt)를 import 하지 않는다 | NFR-03 |
| R-03 | `core` 는 파일을 읽거나 쓰지 않는다 | 로직 테스트에 파일이 필요 없게 함 |
| R-04 | UI 는 `storage` 를 직접 부르지 않고 `AppSession` 을 거친다 | 저장 시점(FR-26)을 한곳에서 관리 |
| R-05 | 난수(`random.Random`)와 경로는 바깥에서 주입한다 | NFR-04 |
| R-06 | 웹 서버는 `127.0.0.1` 에만 묶고, 주소(Host)가 내 PC 가 아니거나 다른 사이트에서 온 POST 는 거절한다 | NFR-02, NFR-09 |

R-01, R-02, R-04 는 `tests/test_architecture.py`, R-06 은 `tests/test_web_flow.py` 로 검사한다.

## 4. 계층 간 인터페이스

### 4.1 데이터 전달 객체

`core/models.py` 의 자료형을 모든 계층이 함께 쓴다. 정의는 프로세스 설계서 §1.3 과 같다. 이 문서에서 더하는 것은 아래 둘이다.

| 이름 | 구성 | 설명 |
|------|------|------|
| `ProgressSummary` | `current_day`, `total_days`, `done_days`, `wrong_list_size` | 메인 화면 표시용 |
| `StartupNotice` | `kind`(`PROGRESS_CORRUPT` / `WORDBOOK_INVALID`), `backup_path` | 시작할 때 사용자에게 알릴 일(DL-04) |

값 객체(`Word`, `DayRange`, `Question`, `Exam`, `ExamResult` 등)는 바꿀 수 없게(frozen) 만든다. `Progress`, `DayRecord`, `WordRecord` 만 바뀐다.

### 4.2 `AppSession` — UI 가 쓰는 창구

`AppSession.open(base_dir, default_csv_path, rng=None)` 으로 만든다. 시작 순서(프로세스 설계서 §4)를 수행하고, 기본 단어장을 읽지 못하면 `WordbookLoadError` 를 올린다.

| 구분 | 멤버 | 반환 | 기록 변경·저장 | FR |
|------|------|------|----------------|----|
| 조회 | `words` | `list[Word]` | — | FR-01 |
| | `wordbook_source` | `DEFAULT` / `CUSTOM` | — | FR-03 |
| | `days` | `list[DayRange]` | — | FR-07 |
| | `startup_notices` | `list[StartupNotice]` | — | FR-28 |
| | `summary()` | `ProgressSummary` | — | FR-09 |
| | `day_status(day_no)` | `DayStatus` | — | FR-08 |
| | `day_words(day_no)` | `list[Word]` | — | FR-07 |
| | `reviewable_days()` | `list[int]` | — | FR-20 (2026-11-25 부터 화면은 쓰지 않음) |
| | `wrong_list()` | `list[WrongEntry]` | — | FR-22 |
| | `wrong_words()` | `list[Word]` (오답 목록 순서) | — | FR-23 |
| 일차 학습 | `complete_memorize(day_no)` | 없음 | O | FR-12 |
| 일차 시험 | `build_day_exam(day_no)` | `Exam` | — | FR-13, FR-14 |
| | `submit_day_exam(day_no, exam, answers)` | `ExamResult` | O | FR-16 ~ FR-19 |
| 오답 시험 | `build_wrong_exam()` | `Exam` | — | FR-24 |
| | `submit_wrong_exam(exam, answers)` | `(ExamResult, list[str])` — 뒤는 목록에서 빠진 단어 | O | FR-25 |
| 단어장 | `check_wordbook_file(path)` | `(list[Word], list[ValidationIssue])` | — | FR-02 |
| | `replace_wordbook(words)` | 없음 | O (초기화) | FR-03, FR-04 |
| | `export_wordbook(path)` | 없음 | — | FR-05 |
| | `export_wrong_list(path)` | 없음 | — | FR-06 |

- "기록 변경·저장"이 O 인 메서드는 돌아오기 전에 `progress.json` 저장까지 끝낸다. UI 는 저장을 따로 부르지 않는다(FR-26).
- 단어장 교체가 `check_wordbook_file` 과 `replace_wordbook` 둘로 나뉜 것은 그 사이에 UI 가 확인(DL-01)을 받아야 하기 때문이다. 웹에서는 검증을 통과한 단어 목록을 `WebState.pending_import` 에 들고 확인 페이지를 보여 준 뒤, `바꾸기` 요청이 오면 `replace_wordbook` 을 부른다.
- 내보내기 메서드는 경로를 받는다. 웹에서는 임시 폴더에 쓰게 한 뒤 그 내용을 다운로드로 보낸다(세션은 고치지 않음).
- 카드 묶음(`core.cards.CardDeck`)은 `web/state.py` 의 `CardStudy` 가 만든다. 저장되지 않는 화면 상태라 세션을 거칠 이유가 없다.

### 4.3 예외 규약

| 예외 | 올리는 곳 | UI 의 처리 |
|------|-----------|-------------|
| `WordbookLoadError` | `AppSession.open` — 기본 단어장을 읽을 수 없음 | 서버를 띄우지 않고 콘솔에 원인을 적고 종료 |
| `ValueError` | 로직 함수 — 잘못된 호출(응시 조건 미달, 미응답 채점 등) | UI 가 버튼 상태로 먼저 막는다. 웹은 주소를 직접 쳐서 요청할 수 있으므로 서버에서도 조건을 확인하고, 어기면 알림 띠를 띄우고 이전 화면으로 돌려보낸다 |
| `OSError` | 저장·내보내기 — 디스크 오류 | 알림 띠(DL-04 저장 실패, 또는 내보내기 실패) |

단어장 검증 실패와 기록 손상은 예외가 아니라 반환값(`ValidationIssue` 목록, `StartupNotice`)으로 전달한다. 예상할 수 있는 사용자 상황이기 때문이다.

### 4.4 화면 전환 규약

2026-11-25 웹 전환으로 바뀌었다(ADR-19). 예전 규약(Qt 시그널 + `MainWindow`)은 ADR-09 에 남아 있다.

- 화면 하나가 URL 하나다(S-01 `/`, S-02 `/cards`, S-03 `/exam`, S-04 `/result`, S-05 `/days?show=`, S-06 `/wrong`, S-07 `/wordbook`, S-08 `/days/<n>`). 시험 화면을 뺀 모든 화면 위에 메뉴 막대(`base.html`)가 있다(ADR-22). 모든 URL 과 전이 규칙은 `web/app.py` 한 파일에 있어 UI/UX 설계서 §4 의 전이도와 나란히 볼 수 있다.
- 화면을 보여 주는 요청은 GET, 기록이나 진행 상태를 바꾸는 요청은 POST 다. POST 는 처리 뒤 GET 화면으로 리다이렉트한다(Post/Redirect/Get). 새로고침·브라우저 '뒤로'로 같은 답이 두 번 제출되지 않는다.
- 앱이 `AppSession` 하나와 `WebState` 하나를 갖는다(`app.extensions`). 서버는 요청을 한 번에 하나만 처리한다(ADR-20).
- 화면은 요청마다 `AppSession` 에서 값을 다시 읽어 그린다. 화면 안에 기록의 사본을 두지 않는다(FR-09).
- 버튼을 켤지 끌지는 서버가 정해 HTML 에 적는다. 템플릿과 `app.js` 는 그리기와 누르는 방법(단축키, 자동 넘김, 확인 대화상자)만 맡는다. 테마(ADR-23)와 발음(ADR-24)은 기록과 무관한 브라우저 쪽 기능이라 `app.js` 만으로 처리한다.
- 화면 흐름 테스트(`tests/test_web_flow.py`)는 Flask 테스트 클라이언트로 요청을 보내 서버·브라우저 없이 흐름을 검증한다. JS 동작은 자동 테스트 범위 밖이라 브라우저에서 직접 확인한다.

### 5.2 경로 규칙 (`paths.py`)

| 함수 | 반환 | 규칙 |
|------|------|------|
| `base_dir()` | 기준 디렉토리 | 소스 실행: 프로젝트 루트(`paths.py` 에서 세 단계 위). PyInstaller 실행(`sys.frozen`): exe 가 있는 폴더 |
| `default_wordbook_path()` | `<기준>/data/toeic_words.csv` | — |
| `userdata_dir()` | `<기준>/userdata` | — |

- 경로는 `paths.py` 에서만 정하고, 다른 모듈은 인자로 받는다(R-05).
- **PyInstaller 배포 방침**: 이번 범위에서는 exe 를 만들지 않는다. 만들게 되면 exe 옆에 `data/` 를 함께 두는 폴더 배포를 기본으로 하고, 단일 파일 배포나 `%APPDATA%` 저장은 그때 결정 기록에 추가한다(ADR-06 재검토 조건).
