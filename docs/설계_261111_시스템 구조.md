## 1. 개요

| 항목 | 내용 |
|------|------|
| 관련 이슈 | #7 [Docs] 시스템 아키텍처·인터페이스 정의서 작성 (간략본) |
| 입력 문서 | 기능 분해도, 데이터 설계서, 프로세스 설계서, UI/UX 설계서, 과제 요건(`ai-agent/uploads/2026-final/`) |
| 후속 | 구현(`src/`), 테스트(`tests/`), `Dockerfile` |
| 과제 요건 | VOCA-NFR-001 ~ 005, VOCA-SUB-031 ~ 037, Dockerfile 규칙 R-01 ~ R-16 |

Flask 웹 애플리케이션 하나다. 같은 코드가 두 방식으로 뜬다.

- **학교 서버 (제출용)**: Docker 컨테이너 안에서 gunicorn 이 `0.0.0.0:8080` 으로 듣고, 앞단 nginx 프록시가 `/2026/voca-<학번>/` 경로로 넘긴다. DB 는 `/data/voca.db` (ADR-29).
- **내 PC**: `python -m smartvoca` 가 `127.0.0.1:8765` 에 개발용 서버를 띄우고 브라우저를 연다. DB 는 `userdata/voca.db` (ADR-18).

외부 API·인터넷 연결은 쓰지 않는다(서버는 인터넷이 막혀 있다). 결정 근거는 `설계_261111_결정 기록.md` 의 ADR-05, ADR-08, ADR-18 ~ ADR-20, ADR-25 ~ ADR-30 을 따른다(ADR-01, ADR-09 는 대체됨).

## 2. 계층 구조

```
┌───────────────────────────────────────────────┐
│ UI 계층            smartvoca.web    (Flask)   │  URL·화면 전이, 폼, HTML 그리기, 화면 상태
└──────────────────────┬────────────────────────┘
                       │ 호출 (한 방향)
┌──────────────────────▼────────────────────────┐
│ 응용 계층          smartvoca.session          │  흐름 조립, 트랜잭션 하나 = 메서드 하나
└─────────┬─────────────────────────┬───────────┘
          │                         │
┌─────────▼──────────┐   ┌──────────▼───────────┐
│ 도메인 로직 계층     │   │ 데이터 접근 계층       │
│ smartvoca.core     │◀──│ smartvoca.storage    │
│ 진도·카드·시험·오답   │   │ SQLite, 단어장 CSV    │
└────────────────────┘   └──────────────────────┘
```

| 계층 | 패키지 | 역할 | 쓸 수 있는 것 |
|------|--------|------|----------------|
| UI | `smartvoca.web` | URL(화면)·폼 처리, 진행 중인 카드·시험 상태(`WebState`), 템플릿·CSS·JS. 학습 규칙(진도·채점·오답)은 갖지 않는다 | `session`, `core.models`(자료형), `core.cards`·`core.exam`·`core.validation`(순수 함수), Flask |
| 응용 | `smartvoca.session` | UI 가 부르는 유일한 창구. 로직 함수를 순서대로 부르고 DB 에 쓴다 | `core`, `storage` |
| 도메인 로직 | `smartvoca.core` | 프로세스 설계서의 계산·상태 변경 규칙, 입력 검증 | 표준 라이브러리만 |
| 데이터 접근 | `smartvoca.storage` | SQL(`sqlite3`), CSV 읽기·쓰기와 검증 | `core.models`, `core.validation`, 표준 라이브러리 |

### 2.1 의존 규칙

| 규칙 | 내용 | 근거 |
|------|------|------|
| R-01 | 호출은 위에서 아래로만 한다. `core`, `storage`, `session` 은 `web` 을 import 하지 않는다 | NFR-03 |
| R-02 | `core`, `storage`, `session` 은 Flask·Werkzeug·Jinja2(와 예전 PyQt)를 import 하지 않는다 | NFR-03 |
| R-03 | `core` 는 파일·DB 를 읽거나 쓰지 않는다 | 로직 테스트에 파일이 필요 없게 함 |
| R-04 | UI 는 `storage` 를 직접 부르지 않고 `AppSession` 을 거친다 | 저장 시점(FR-26)과 트랜잭션을 한곳에서 관리 |
| R-05 | 난수(`random.Random`)·시계(`clock`)·DB 경로는 바깥에서 주입한다 | NFR-04, VOCA-NFR-005 |
| R-06 | 주소는 `url_for` 로만 만든다(호스트를 쓰지 않음). 다른 사이트에서 온 POST 는 거절한다(§4.5). 비밀값은 환경변수로 받는다 | VOCA-SUB-033, 036, VOCA-NFR-004 (2026-11-25 개정, 이전: `127.0.0.1` 에만 묶음) |

R-01, R-02, R-04 는 `tests/test_architecture.py`, R-06 은 `tests/test_web_flow.py`·`tests/test_deploy.py` 로 검사한다.

## 4. 계층 간 인터페이스

### 4.1 데이터 전달 객체

`core/models.py` 의 자료형을 모든 계층이 함께 쓴다. 값 객체는 모두 바꿀 수 없게(frozen) 만든다. 주요 객체는 아래와 같다(자세한 필드는 프로세스 설계서 §1.3, 데이터 설계서).

| 이름 | 설명 |
|------|------|
| `Word(index, word, meaning, id)` | 단어. `id` 는 DB 번호, `index` 는 단어장 순서 |
| `Settings` | 하루 학습량, 복습 카드 수, 시험 문제 수·방향·형식 기본값 |
| `StudyCard(word, kind)` | 카드 1장. `kind` = 새 단어 / 복습 / 오답 |
| `Question`, `Exam`, `Answer`, `ExamResult`, `ItemResult` | 시험지·답(보기 번호 또는 글)·채점 결과 |
| `ProgressSummary` | 현재 일차, 일차 수, 완료·암기 일차 수, 오답 수, 외운 단어 수, 전체 단어 수 |
| `ParsedWordbook`, `ValidationIssue`, `ImportReport` | CSV 검증·가져오기 결과 |
| `LearningStats(TrendPoint, FrequentWrong …)` | 통계 화면 값 |

2026-11-25 부터 바뀌는 기록 객체(`Progress`, `DayRecord`, `WordRecord`)와 `StartupNotice` 는 없다. 기록은 DB 에만 있다.

### 4.2 `AppSession` — UI 가 쓰는 창구

`AppSession.open(db_path, default_csv_path, rng=None, clock=None)` 으로 만든다. 테이블이 없으면 만들고 처음이면 기본 단어장을 넣는다(`db.init_db`, VOCA-NFR-003). 기본 단어장을 읽지 못하면 `ValueError` 를 올린다.

| 구분 | 멤버 | 반환 | DB 쓰기 | 요구사항 |
|------|------|------|---------|----------|
| 조회 | `words()` | `list[Word]` | — | VOCA-FR-002 |
| | `settings()` | `Settings` | — | VOCA-FR-061 |
| | `days()` | `list[(DayRange, DayStatus, list[Word])]` | — | VOCA-FR-011 |
| | `day(day_no)` | `(DayStatus, list[Word])` 또는 `None` | — | VOCA-FR-011 |
| | `summary()` | `ProgressSummary` | — | VOCA-FR-031 |
| | `wrong_list()` / `wrong_words()` | `list[WrongEntry]` / `list[Word]` | — | VOCA-FR-025 |
| | `stats()` | `LearningStats` | — | VOCA-FR-031 ~ 034 |
| 학습 | `day_cards(day_no)` | `list[StudyCard]` (그 일차 단어 + 복습 카드) | — | VOCA-FR-012, 013 |
| | `complete_memorize(day_no, cards)` | 없음 | O `study_log` | VOCA-FR-014 |
| 시험 | `build_exam(kind, direction, format, day_no, count)` | `Exam` | — | VOCA-FR-021 ~ 024 |
| | `submit_exam(kind, exam, answers, direction, format, day_no)` | `SubmitOutcome(result, graduated)` | O 시험 이력·오답 목록 | VOCA-FR-025, 026 |
| 단어 | `get_word(id)`, `add_word(word, meaning)`, `update_word(id, word, meaning)`, `delete_word(id)` | `Word` / 없음 | O `word` | VOCA-FR-001, 002 |
| CSV | `check_wordbook_upload(bytes)` | `(ParsedWordbook \| None, list[ValidationIssue])` | — | VOCA-FR-003 |
| | `import_wordbook(parsed, mode)` | `ImportReport` | O (바꾸기면 기록 초기화) | VOCA-FR-003 |
| | `export_wordbook_csv()` / `export_wrong_list_csv()` | `bytes` | — | FR-05, FR-06 |
| 설정 | `save_settings(settings)` | 없음 | O `setting` | VOCA-FR-062 |

- 쓰는 메서드 하나가 트랜잭션 하나다. 돌아오면 DB 에 반영돼 있고, 예외면 아무것도 바뀌지 않는다. UI 는 저장을 따로 부르지 않는다(FR-26).
- CSV 가져오기가 `check_wordbook_upload` 와 `import_wordbook` 둘로 나뉜 것은 그 사이에 UI 가 방식(추가/바꾸기) 선택과 확인(DL-01)을 받아야 하기 때문이다. 검증을 통과한 결과는 `WebState.pending_import` 에 들고 있는다.
- 업로드·내보내기는 바이트로 주고받는다. 서버 디스크에 파일을 쓰지 않는다(R-06 쓰기 제한).
- 카드 묶음(`core.cards.CardDeck`)은 `web/state.py` 의 `CardStudy` 가 만든다. 저장되지 않는 화면 상태라 세션을 거칠 이유가 없다.

### 4.3 예외 규약

| 예외 | 올리는 곳 | UI 의 처리 |
|------|-----------|-------------|
| `ValueError` | `AppSession.open` — 기본 단어장을 읽을 수 없음 | 서버를 띄우지 않는다 (콘솔·gunicorn 로그에 원인) |
| `ValueError` | 잘못된 호출(응시 조건 미달, 빈 오답 목록, 4지선다를 만들 단어 부족 등) | 버튼 상태로 먼저 막고, 주소를 직접 쳐도 알림 띠를 띄우고 이전 화면으로 |
| `WordInputError(problems)` | 단어 등록·수정 — 빈 칸, 너무 긺, 중복 | 입력 화면에 문제 목록을 보여 준다 |
| `LookupError` | 없는 단어 수정·삭제 | 알림 띠 후 단어 관리로 |
| `sqlite3.Error`, `OSError` | DB 쓰기 실패 | 알림 띠(DL-04 저장 실패) |

CSV 검증 실패는 예외가 아니라 반환값(`ValidationIssue` 목록)으로 전달한다. 예상할 수 있는 사용자 상황이기 때문이다.

### 4.4 화면 전환 규약

- 화면 하나가 URL 하나다. 모든 URL 은 블루프린트 `main` 에 있고, 템플릿·JS 의 주소는 `url_for` 로 만들어 `/` 로 시작하는 경로만 쓴다(호스트 없음, R-04). 프록시가 앞에 붙이는 `/2026/voca-<학번>` 은 서버가 처리한다.

| 화면 | URL |
|------|-----|
| S-01 홈 | `GET /` |
| S-02 카드 | `GET /cards` (`POST /study/today`, `/study/day/<n>`, `/study/wrong`, `/cards/next·prev·hide·action`) |
| S-03 시험 | `GET /exam` (`POST /exam/answer·goto·abort·submit`) |
| S-04 결과 | `GET /result` |
| S-05·S-08 일차 | `GET /days?show=`, `GET /days/<n>` (`POST /exam/day/<n>`) |
| S-06 오답 | `GET /wrong` |
| S-07 단어 관리 | `GET /wordbook`, `POST /words`, `GET·POST /words/<id>/edit`, `POST /words/<id>/delete`, `POST /wordbook/import[/confirm·/cancel]`, `GET /export/wordbook.csv`, `GET /export/wrong_words.csv` |
| S-09 시험 설정 | `GET /exam/setup`, `POST /exam/start` |
| S-10 통계 | `GET /stats` |
| S-11 설정 | `GET·POST /settings` |

- 시험 화면을 뺀 모든 화면 위에 메뉴 막대(`base.html`, 7개 메뉴 `NAV_ITEMS`)가 있다(ADR-22).
- 화면을 보여 주는 요청은 GET, 기록이나 진행 상태를 바꾸는 요청은 POST 다. POST 는 처리 뒤 GET 화면으로 리다이렉트한다(Post/Redirect/Get). 새로고침·'뒤로'로 같은 답이 두 번 제출되지 않는다.
- 화면은 요청마다 `AppSession` 에서 값을 다시 읽어 그린다. 화면 안에 기록의 사본을 두지 않는다(FR-09).
- 버튼을 켤지 끌지는 서버(`routes_*.py`, `state.py`)가 정해 HTML 에 적는다. 템플릿과 `app.js` 는 그리기와 누르는 방법만 맡는다.
- 화면 흐름 테스트(`tests/test_web_flow.py`)는 Flask 테스트 클라이언트로 서버·브라우저 없이 흐름을 검증한다. JS 동작은 브라우저에서 직접 확인한다.

### 4.5 화면 상태와 보안 (ADR-30)

| 항목 | 규칙 |
|------|------|
| 화면 상태 | 진행 중인 카드·시험·결과·가져오기 대기는 `WebState` 에 둔다. 브라우저마다 따로다: 서명된 쿠키 `sid`(무작위 `secrets.token_urlsafe(16)`)로 `StateStore` 에서 찾는다 |
| 상태 개수 | `StateStore` 는 최근 500개만 두고 오래 안 쓴 것부터 지운다(LRU). 접근은 잠금(`threading.Lock`)으로 보호 |
| 워커 수 | gunicorn 워커 1개. 상태가 프로세스 메모리에 있으므로 여러 워커면 요청마다 다른 상태를 보게 된다 (ADR-29) |
| 출처 검사 | POST 의 `Origin`(없으면 `Referer`) 호스트가 `request.host` 와 다르면 403. 프록시가 https→http 로 넘기므로 스킴은 비교하지 않는다 |
| 쿠키 | `SESSION_COOKIE_SAMESITE=Lax`, 서명 키는 환경변수 `SECRET_KEY` (없으면 기동 시 무작위) |
| 업로드 | `MAX_CONTENT_LENGTH` 5MB, 넘으면 알림 띠 |
| 출력 | Jinja2 자동 이스케이프. 단어·뜻은 사용자가 넣은 글이라 그대로 HTML 로 내보내지 않는다 |

기록(DB)은 모든 브라우저가 기본 사용자 1명(`user_id=1`)을 함께 쓴다. 로그인은 범위 밖이다(VOCA-FR-041 ~ 043 미구현, 데이터 설계서 DD-05).

## 6. 학교 서버 배포 (ADR-29)

### 6.1 흐름

```
GitHub 리포 (Public) ──제출 SHA──▶ 학교 서버: docker build (리포 루트 Dockerfile)
                                    └▶ 컨테이너 실행 (UID 10001, cap-drop ALL, 읽기 전용 + /data·/tmp)
브라우저 ─https─▶ nginx /2026/voca-<학번>/ ─http─▶ gunicorn 0.0.0.0:8080 ─▶ smartvoca.web.wsgi:app ─▶ /data/voca.db
```

푸시하면 `.github/workflows/docker-check.yml` 이 같은 조건(빌드, UID, 포트, 쓰기 제한, 인터넷 차단)으로 컨테이너를 띄워 확인한다. PC 에 Docker 데몬이 없을 때는 `tests/test_deploy.py` 가 Dockerfile 규칙을 미리 검사한다.

### 6.2 이미지 구성 (`Dockerfile`)

| 단계 | 내용 |
|------|------|
| 기반 | `python:3.12-slim` |
| 환경 | `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, `PYTHONPATH=/app/src`, `HOME=/tmp`, `DB_PATH=/data/voca.db` |
| 의존성 | `COPY requirements.txt` → `pip install --no-cache-dir` (소스보다 먼저, 캐시 재사용) |
| 소스 | `COPY src`, `COPY data` (기본 단어장) |
| 사용자 | `useradd --uid 10001`, `mkdir /data`, `chown 10001:10001 /data`, `USER 10001` |
| 실행 | `CMD ["gunicorn", "--bind", "0.0.0.0:8080", "--workers", "1", "--timeout", "60", "--access-logfile", "-", "smartvoca.web.wsgi:app"]` |

### 6.3 서버 규칙 대응 (R-01 ~ R-16)

| 규칙 | 요구 | 대응 | 검사 |
