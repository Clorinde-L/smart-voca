## 3. 설계 결정 (결정 기록에 ADR-25~31 로 올림)

### ADR-25 저장소를 SQLite 로 전환
- **배경**: 과제가 DB 이력 관리와 SQLite 를 요구한다 (NFR-002).
- **대안**: (1) JSON 유지 + 이력만 SQLite (2) 전부 SQLite.
- **결정 근거**: (2). 단어 CRUD·이력·통계가 모두 한 DB 에 있어야 SQL 로 집계할 수 있다(FR-034). 표준 라이브러리 `sqlite3` 라 의존성이 늘지 않는다.

### ADR-26 일차 상태를 단어 단위 이력에서 계산
- **배경**: 하루 학습량을 바꾸거나 단어를 추가·삭제하면 일차 번호가 달라진다. 일차별 플래그를 저장하면 어긋난다.
- **결정**: 일차는 저장하지 않는다(기존과 같음). "암기 완료" = 그 일차의 모든 단어가 `study_log` 에 있음, "완료" = 모든 단어가 일차 시험 문항(`exam_item`, 종류 `day`)에 있음.
- **결과**: 학습량을 바꿔도 이미 외운 단어는 외운 것으로 남는다. 단어를 추가하면 마지막 일차가 다시 "학습 전"이 될 수 있다(그 단어를 아직 안 봤으므로 맞는 표시).

### ADR-27 시험 형식·방향과 가중 출제
- 형식: 4지선다, 단답형, OX. 방향: 영→한, 한→영, 섞기(문제마다 무작위).
- 단답형 채점: 한→영은 대소문자·앞뒤 공백 무시하고 영단어와 같으면 정답. 영→한은 뜻 칸을 품사 표시(`[명]`)·쉼표·세미콜론으로 나눈 조각 중 하나와 같으면 정답(띄어쓰기·괄호 안 내용 무시).
- OX: 보기 하나를 보여 주고 맞는 짝인지 고른다. 절반은 정답 짝, 절반은 다른 뜻.
- 가중치(실력 시험): `1 + 3·(시험 본 적 없음) + min(마지막 시험 후 지난 날, 30)/10 + 2·누적 오답 횟수`. 가중치 비례 비복원 추출(Efraimidis–Spirakis). 난수는 주입한 `random.Random` 만 쓴다(NFR-04 시드 재현 유지).
- 시험 종류: 일차 시험(그 일차 단어 전부), 오답 시험(오답 목록 전부), **실력 시험(문제 수 지정, 가중 출제 — FR-021·022)**.

### ADR-28 CSV 가져오기의 중복 처리
- 헤더는 `word,meaning` 과 `영단어,뜻` 둘 다 받는다.
- **추가**: 이미 있는 영단어(대소문자 무시)는 건너뛰고 기존 뜻을 유지한다. 파일 안에서 중복이면 첫 줄만 쓴다. 건너뛴 수를 알려 준다.
- **바꾸기**: 단어·이력을 모두 지우고 파일의 단어로 새로 시작한다(기존 ADR-03 의 확인 대화상자 유지).

### ADR-29 서버 배포 방식
- 컨테이너: `python:3.12-slim`, gunicorn 워커 1개(sync), `0.0.0.0:8080`, UID 10001, `DB_PATH=/data/voca.db`.
- 워커를 1개로 두는 이유: 진행 중인 카드·시험 상태를 서버 메모리에 두기 때문(ADR-20). 시연 규모에 충분하다.
- 로컬 실행(`python -m smartvoca`)은 그대로 127.0.0.1 + 브라우저 자동 열기. gunicorn 은 Windows 에서 돌지 않으므로 로컬은 werkzeug 서버를 쓴다.
- NFR-02(127.0.0.1 전용)를 "로컬 실행은 127.0.0.1, 서버 배포는 컨테이너 안 0.0.0.0:8080" 으로 바꾼다.

### ADR-30 화면 상태를 브라우저마다 분리 (ADR-20 변경)
- 서버에 여러 사람이 접속하므로 진행 중인 카드·시험을 쿠키의 무작위 ID 별로 따로 둔다. 학습 기록은 기본 사용자(user_id=1) 하나에 쌓는다 (로그인을 넣을 때 계정별로 나눈다).
- Host 허용 목록은 없애고, POST 의 Origin/Referer 는 **호스트 부분만** 비교한다(프록시 뒤에서 http/https 가 달라질 수 있음).

### ADR-31 문서 이름에 버전 표기 (2026-11-18 결정 변경)
- 과제(SUB 4.2)가 `분류_yymmdd_제목 vX.X.md` 를 요구한다. `docs/` 문서 이름에 현재 버전을 붙이고, 버전을 올릴 때 `git mv` 로 이름을 바꾸고 참조를 함께 고친다.

## 4. 데이터 설계 (SQLite)

| 테이블 | 열 | 비고 |
|--------|----|------|
| `app_user` | `id` PK, `name`, `created_at` | 기본 사용자 1명(`guest`) |
| `word` | `id` PK, `word` UNIQUE COLLATE NOCASE, `meaning`, `created_at`, `updated_at` | `id` 순서가 단어장 순서 |
| `study_log` | `id` PK, `user_id`, `word_id`(삭제 시 NULL), `word`, `day_no`, `kind`(new/review/wrong), `studied_at` | FR-014 |
| `exam_session` | `id` PK, `user_id`, `kind`(day/wrong/random), `day_no`, `direction`, `format`, `total`, `correct`, `finished_at` | FR-026·032 |
| `exam_item` | `id` PK, `session_id`, `user_id`, `word_id`, `word`, `format`, `direction`, `prompt`, `correct_answer`, `given_answer`, `is_correct`, `answered_at` | FR-026 |
| `wrong_word` | `user_id`, `word_id` (PK 둘), `wrong_count`, `streak`, `in_list` | 오답 목록(연속 정답 3회 졸업 규칙 FR-25) |
| `setting` | `user_id` PK, `day_size`, `review_count`, `exam_count`, `exam_direction`, `exam_format` | FR-061·062 |

- 단어를 지워도 이력은 남긴다(`word` 문자열을 이력에 함께 저장, `word_id` 는 NULL). `wrong_word` 는 함께 지운다.
- 날짜는 ISO 문자열(로컬 시각). 날짜별 정답률은 `substr(finished_at,1,10)` 로 묶는다.

- `pytest`: 로직(형식별 채점, 가중 추출 재현성, 복습 고르기, 일차 상태), 저장소(스키마 자동 생성·시드·CRUD·통계 SQL), 세션, 화면 흐름(Flask 테스트 클라이언트), 계층 규칙.
- 배포 조건: Docker 가 PC 에 없으면 점검 워크플로(Actions)로 확인한다. 로컬에서는 `DB_PATH` 를 임시 폴더로 주고 앱을 띄워 첫 화면·재시작 후 데이터 유지를 확인한다.
